# 변경 이력

[English](CHANGELOG.md) | [한국어](CHANGELOG.ko.md)

`memnest` Rust 엔진의 주요 변경을 기록합니다.

## [출시 전]

### 보안

- 다른 사이트에서 온 요청: `Origin`은 요청을 받은 호스트와 포트를 가리킬 때만 받습니다(`localhost`, `127.0.0.1`, `[::1]`은 같은 호스트로 봅니다). 전에는 아무 IP 주소나 다른 로컬 포트도 통과했습니다. `Sec-Fetch-Site: cross-site`가 붙은 요청은 거절하고, `POST /mcp`는 본문이 `application/json`이 아니면 415로 답합니다.
- 작업 카드: `task-cards`와 `task-cards-done` 컬렉션은 작업 카드 경로만 쓸 수 있습니다. `memory_remember`, `memory_update`, `/add`, `/update`로는 카드를 만들거나 고치거나 옮길 수 없으므로, 저장된 글이 카드나 사용자 발언인 척할 수 없습니다. 카드 삭제는 그대로 됩니다. 제목은 한 줄 120자로 자르고 `<`와 `>`를 바꾸며, 모델에게 보여 주는 카드 글은 안내문 태그를 닫을 수 없습니다. `POST /task-card`는 사용자 메시지를 직접 기록하는 호스트(pi 확장)가 보낸 메시지를 받습니다. MCP 도구는 받지 않습니다.
- 금고: `MEMNEST_TOKEN`도 접근 정책도 없을 때에도 `/secrets` 경로와 `POST /mcp`의 `secret_*` 도구는 bearer 토큰이 필요합니다. 서비스가 설치별 토큰을 `<data-dir>/api-token`(권한 0600)에 쓰고, 이 모드에서는 그 토큰을 요구합니다. stdio MCP는 그대로입니다.
- 프로세스가 시작할 때마다 umask를 077로 두고 데이터 폴더 권한을 0700으로 맞춥니다. 배포용 systemd 유닛에 `UMask=0077`을 넣었고, 설치 스크립트는 폴더를 0700으로 만듭니다.
- 시스템 모드 systemd 유닛에 `StateDirectoryMode=0700`과 `ProtectSystem=strict`를 넣었습니다. 쓰기 잠금 파일이 `/var/lib/.memnest.writer.lock`이라서 `/var/lib`은 쓸 수 있게 둡니다. 이미 설치된 유닛 파일은 업그레이드 때 다시 쓰지 않습니다.
- 가리기 대상에 JWT, Stripe `sk_live_`/`sk_test_`/`rk_live_`/`rk_test_` 키, GitLab `glpat-`, `npm_`, Hugging Face `hf_`, Slack `xapp-`와 `xoxe-`, AWS `ASIA` 임시 키를 더했습니다.
- 휴지통에 있는 카드를 `memory_update`나 `/update`로 고친 뒤 복원하는 길을 막았습니다. 저장하는 카드 본문에 "User's own words" 구역을 흉내 낸 제목이 있으면 그 줄부터 아래를 잘라 냅니다.
- 토큰 패턴이 ASCII 단어 경계를 써서, 토큰 바로 뒤에 한글이 붙어도(`hf_...입니다`) 가립니다. Slack 앱 토큰은 `xapp-<숫자>-` 모양일 때만 가려서 `xapp-sn-watcher` 같은 패키지 이름은 그대로 둡니다.
- RustSec 권고에 따른 의존성 갱신: `rusqlite` 0.41과 `libsqlite3-sys` 0.39(내장 SQLite CVE), `zstd` 0.13.4와 `zstd-safe` 7.4, `quinn-proto` 0.11.19, `webpki-roots` 1.0.11, `crossbeam-epoch` 0.9.21, `tokio` 1.54, `anyhow` 1.0.104, `memmap2` 0.9.12. `cargo audit` 취약점은 0건입니다. `lru`(unsound)와 `paste`(유지보수 중단)는 간접 의존성 경고로 남아 있고, 의존성 트리에 고친 버전이 없습니다.
- `MEMNEST_TOKEN`을 일정 시간 비교로 확인합니다.
- 읽기 전용 MCP 게이트웨이는 주소의 비밀 값을 일정 시간 비교로 확인합니다. `MEMNEST_GATEWAY_TOOLS`에 넣더라도 `memory_remember`, `memory_update`, `memory_delete`, `task_card`와 모든 `secret_*` 도구를 거절하고, 호출을 넘기기 전에 `evidence_only`를 지웁니다.
- `--backup-dir`은 백업에 금고 키가 들어 있다는 경고를 출력합니다. 복원이 계속 되도록 키는 그대로 복사합니다.
- `memnest hook`과 `memnest watch`는 루프백이 아닌 주소에 일반 HTTP로 `MEMNEST_TOKEN`을 보내지 않습니다.

### 추가

- `POST /recent`는 저장한 기억(chunk type manual)을 사람이 직접 보는 화면용으로 나열합니다. pi 확장의 `/memnest-recent`, `/memnest-review`가 씁니다. MCP 도구는 아닙니다. `project`나 `cwd`(`/search`와 같은 방식으로 범위 결정), `rules_only`(중요도 `preference` 또는 종류 `rule`), `oldest_first`, `limit`(1~50, 기본 20)을 받고, 걸러내기와 정렬을 SQL에서 해서 대화 기록 행은 읽지 않습니다. 최신순은 마지막 저장 기준이고, `oldest_first`는 만든 날과 마지막 확인일 중 늦은 날 기준입니다. 민감 기억, 휴지통, 대체된 판, 작업 카드는 절대 돌려주지 않고, 프로젝트 권한이 있는 호출자는 읽을 수 있는 프로젝트만 받습니다. 글은 검색과 같이 가려서 줍니다.
- `POST /reviewed {id}`는 저장한 기억이 아직 맞다고 사람이 확인했음을 메타데이터의 `reviewed_at`에 기록합니다. 그 밖에는 아무것도 바꾸지 않고(글, 임베딩, `updated_at`, 색인, 순위 그대로) `/update`와 같은 쓰기 검사를 거칩니다. `/add`는 받은 `reviewed_at`을 무시하고, 기억 글을 고치면 이 날짜는 지워집니다.

- 언어 모델을 쓰지 않는 검색 벤치마크: `benchmarks/retrieval` 하네스(LoCoMo 전체, LongMemEval-S 고정 표본 100문항), 질문별 결과 파일, 놓친 질문 분석, 그리고 [docs/benchmarks.ko.md](../docs/benchmarks.ko.md) 문서. 수치는 검색 회수율이지 답변 정확도가 아니며, LLM이 채점한 점수와 비교할 수 없습니다.
- 작업공간 범위로 검색했을 때(`project`를 주지 않은 검색) 다른 프로젝트에 확실히 더 잘 맞는 기억이 있으면 알려 줍니다. 결과 끝에 한 줄이 붙습니다. 프로젝트 이름을 최대 3개, 프로젝트마다 더 잘 맞는 저장 기억 수, 그리고 `project="<이름>"`이나 `project="all"`로 다시 검색하라는 안내가 들어갑니다. 검색 범위 자체는 바뀌지 않고, 다른 프로젝트의 내용은 돌려주지 않습니다. 이 줄은 MCP `memory_search` 결과 글, `/search`와 `/context`의 선택 필드 `scope_hint`, `memnest hook`이 쓰는 문맥 묶음에 나옵니다. 호출자가 프로젝트를 지정했거나, 최신순으로 검색했거나, 접근 정책으로 읽을 프로젝트가 제한돼 있으면 붙지 않습니다. 휴지통, 대체된 기록, 작업 카드, 민감 기록, 호출자가 읽을 수 없는 프로젝트는 이름을 대지 않습니다. 실제 프롬프트 47개 중 3개에서 나왔습니다. 3개 모두 프롬프트가 다루는 프로젝트를 가리켰고, 그중 1개는 세어진 기억이 바로 그 답이었습니다. 모호한 프롬프트 24개에서는 한 번도 나오지 않았습니다. 방법과 한계는 `docs/search-relevance.md`에 있습니다.
- 새 작업 카드를 저장하면, 그 작업에 대해 이미 저장돼 있던 규칙과 선호 기억을 id와 함께 답에 붙입니다. 모델이 아직 유효한 것을 카드에 옮겨 적을 수 있습니다. 전에는 카드가 만들어진 뒤에 한 말만 카드에 들어가서, 실제 사용에서 카드보다 5일 먼저 저장된 규칙이 사용자가 다시 말할 때까지 빠져 있었습니다. 관련 기억이 가장 많은 프로젝트에서 최신순으로 먼저 고르고, 그다음 검색 결과에서 골라 최대 10줄을 보여 줍니다.
- 관리자 권한 없이 설치하는 네이티브 Windows 지원(64비트 x86, Windows 10/11). `irm https://raw.githubusercontent.com/Blue-B/memnest/main/core/scripts/install.ps1 | iex`가 릴리스 zip을 내려받아 SHA-256을 확인하고 `install-windows.ps1`을 실행합니다. 설치 위치는 `%LOCALAPPDATA%\memnest`, 데이터는 `%USERPROFILE%\.memnest`이고, 로그인 때 시작하는 예약 작업 두 개(서버와 `memnest watch`)를 등록합니다. `docs/operations.ko.md`를 참고하세요.
- 릴리스에 `memnest-<버전>-x86_64-pc-windows-msvc.zip`과 `.sha256`이 포함됩니다. Microsoft Visual C++ 재배포 가능 패키지(x64)가 필요하고, 코드 서명은 되어 있지 않습니다.

### 변경

- 검색 순위: 이제 결과의 순서는 질문 낱말이 기억에 얼마나 들어 있는지가 아니라 두 검색(의미와 키워드)이 주로 정합니다. 전에는 낱말이 겹칠 때 주는 가산점(최대 0.15)이 두 검색의 순위에서 나오는 점수(최대 0.033)보다 몇 배 컸습니다. 그래서 질문 낱말을 더 많이 담은 긴 글이, 두 검색이 모두 1위로 꼽은 기억을 앞질렀습니다. 이제 두 순위 목록을 RRF k=10으로 합치되 키워드 목록은 절반만 반영하고, 결과 점수는 0.10 x 순위 + 0.08 x 질문 낱말 비율에 전과 같은 중요도, 종류, 나이 항을 더한 값입니다. 언어 모델 없이, 배포된 0.5.1과 이 빌드를 상수를 정하는 데 쓰지 않은 데이터로 잰 결과입니다. LoCoMo 대화 5~9(범주 1~4, 질문 776개)는 R@1 39.8에서 42.9, R@5 60.2에서 68.7, R@10 69.5에서 76.8입니다(R@10에서 76개를 새로 맞히고 19개를 잃음). 두 번째 LongMemEval-S 표본 100개는 세션 R@1 83에서 94, R@5 96에서 98, R@10 98에서 99입니다(R@1에서 11개를 새로 맞히고 잃은 것 없음). 상수를 정하는 데 쓴 데이터에서는 LoCoMo 대화 0~4의 R@10이 68.8에서 79.1, 첫 LongMemEval-S 표본의 세션 R@1이 83에서 89, R@5가 91에서 94입니다. 나빠진 수치가 하나 있습니다. 채점 대상이 아닌 LoCoMo adversarial 범주의 R@1이 30.9에서 26.9가 되었습니다(R@10은 58.1에서 66.6으로 올랐습니다). 실제 저장소 복사본에서 저장 기억 40개를 질문으로 찾았을 때, 그 기억이 1위로 나온 질문은 13개에서 16개, 처음 3개 안에 나온 질문은 24개에서 26개가 되었습니다. 질문 낱말이 하나도 없는 기억은 순위로 최대 0.049만 받으므로, pi 확장이 저장 기억을 자동으로 넣는 기준인 0.25에는 전과 같이 닿지 못하며 이것은 테스트로 고정했습니다. 후보 수, 거리 한계, MMR, 임베딩 모델은 그대로이고, 색인을 다시 만들지 않으며 새 의존성도 없습니다. 표와 측정 방법은 [docs/benchmarks.ko.md](../docs/benchmarks.ko.md)와 `benchmarks/retrieval/ANALYSIS.md` 8절에 있습니다.
- 자동 회상(`memnest hook`이 쓰는 `/context`)은 프롬프트와 주제가 같은 기억만 넣습니다. 전에는 관련이 없어도 상위 3개를 넣었습니다. 프롬프트의 주제어 2개가 기억에 있고 임베딩 거리가 0.18 이하이거나, 주제어 1개가 있고 0.13 이하이거나, 기억이 다른 언어(한국어인지 아닌지)로 쓰였고 프롬프트에 주제어가 2개 이상이며 0.21 이하이면 남깁니다. "그러면", "지금", "then", "now" 같은 말은 주제어로 세지 않습니다. 실제 프롬프트 47개(구체적 23개, 모호한 24개)에서 무관한 기억 주입이 95개에서 14개로(프롬프트당 2.0개에서 0.3개로) 줄었고, 관련 기억 12개는 모두 남았고, 아무것도 넣지 않는 모호한 프롬프트가 24개 중 4개에서 24개로 늘었습니다. 약하게 관련된 기억은 10개에서 4개로 줄었고, 남은 무관한 14개 중 6개는 빈자리에 새로 들어온 것입니다. 통과한 기억이 없으면 `memnest hook`은 문맥을 아예 붙이지 않습니다. 직접 하는 검색(`memory_search`, `/search`)은 걸러내지 않습니다.
- 문서를 바로잡았습니다: 고정 설치 예시를 v0.5.1로 올렸고, 지원 버전 표를 0.5.x로 고쳤고, 어댑터 문서의 pi 도구 수를 6개로 고쳤고, 한국어로만 쓰인 문서로 가는 링크에 한국어라고 표시했습니다.
- README의 작업 카드 설명이 다시 돌려 본 결과를 정확히 적습니다(카드가 있을 때 블라인드 채점 3번 중 3번, 없을 때 3번 중 0번 방침을 지킴). 카드가 있다고 모델이 반드시 따르는 것은 아니라는 문구도 넣었습니다.
- `install-windows.ps1`은 더 이상 관리자 권한의 WinSW 서비스를 설치하지 않고 데이터를 `%ProgramData%\Memnest`에 두지 않습니다. 서비스 계정은 사용자의 대화 기록을 읽을 수 없기 때문입니다. `uninstall-windows.ps1`은 그런 설치가 남아 있으면 경고하고, 데이터를 옮기는 방법은 `docs/operations.ko.md`에 있습니다.
- 릴리스 압축 파일에는 해당 운영체제 설치에 쓰는 스크립트와 서비스 템플릿만 들어갑니다. Linux와 macOS 압축 파일에 PowerShell, 테스트, 개발용 스크립트가 더 이상 들어가지 않습니다.

### 수정

- 검색: 질문에 `Caroline's` 같은 어포스트로피, 끝의 마침표, 앞의 `-`나 `+`, 여는 괄호, 끝의 `AND`/`OR`가 있으면 키워드 검색 파서가 거절했고, 그 오류가 버려져서 벡터 검색만 돌고 결과가 3개만 나왔습니다. 이제 그런 질문은 낱말만 남겨 다시 검색합니다. 검색 벤치마크에서 LoCoMo 질문 1,986개 중 330개가 여기에 걸렸습니다. 수정 뒤 LoCoMo에서 처음 10개 결과의 회수율은 69.1%에서 70.7%로 올랐고, 영향을 받는 LongMemEval 표본 질문 17개에서는 맞는 세션이 1위인 경우가 16개에서 11개로 줄었습니다(처음 3개 안에는 그대로 16개). 둘 다 [docs/benchmarks.ko.md](../docs/benchmarks.ko.md)에 있습니다.
- Windows: 같은 폴더인데도 `memnest evidence`가 훅이나 MCP와 다른 작업공간 ID를 쓰던 문제를 고쳤습니다. 정규화된 경로가 `\\?\`로 시작해서 생긴 문제입니다.
- Windows: `memnest watch`의 기본 대화 기록 폴더를 역슬래시로 표기해, 나중에 같은 폴더를 `--path`로 지정해도 같은 파일로 인식합니다.
- Windows의 `setup-clients.py`가 클라이언트 설정 파일을 시스템 코드 페이지가 아니라 UTF-8로 읽고, `memnest.exe`를 자기 훅으로 인식해 다시 실행해도 중복으로 추가하지 않으며, Git Bash와 cmd에서 모두 실행되는 훅·복구 명령을 씁니다.

### 제거

- 쓰이지 않던 코드를 지웠습니다: `SessionSummary`, `SearchResult` 타입, `Database::insert_summary`, `get_summaries`, `recent_chunks`, 임베더의 `model_name`, `encode`, `encode_batch`, `TextIndex::add`, `remove`, `replace_all_with_project`, 그리고 맥락 없는 `crypto::encrypt`, `crypto::decrypt`. 행 단위로 묶는 `encrypt_bound`, `decrypt_bound`는 예전 암호 대체 경로를 포함해 그대로입니다. `text_search`와 `add_text_doc`은 이제 테스트에서만 존재합니다.

### 업그레이드할 때

### 추가

  - MCP `task_card` 도구와 `POST /task-card`로 카드를 저장, 목록, 열기, 끝내기, 닫기 합니다.
  - `memnest hook`이 `POST /task-card/hook`을 통해 Claude Code와 Codex의 `SessionStart`와 `UserPromptSubmit`을 처리합니다. 세션 첫 프롬프트에 카드 목록을 보여 주고, 사용자 메시지를 열린 카드에 원문 그대로 기록합니다. 압축 뒤에는 규칙과 사용자 최근 말을 다시 넣습니다.
  - 카드가 없으면 첫 프롬프트에 언제 카드를 저장할지 알려 주며, 사용자가 이전 작업을 이어 갈 때도 포함합니다. 빈 `list` 응답은 "새 작업으로 취급하라" 대신 카드를 저장하라고 합니다. 열린 카드 없이 압축되면 세션당 한 번 알려 줍니다.
  - 열린 카드가 사용자 메시지 8개 동안 저장되지 않으면, 대화가 다른 일로 넘어갔으면 닫고 아니면 저장하라고 한 번 알려 줍니다.
  - `memnest hook --no-recall`은 자동 회상 없이 작업 카드만 처리합니다.
  - 설치 스크립트가 기본으로 Claude Code(`~/.claude/settings.json`)와 Codex(`~/.codex/hooks.json`)에 이 훅을 넣고, Codex가 `task_card`를 승인 질문 없이 부를 수 있게 합니다. 회상은 여전히 `--autocontext`로 직접 켭니다.

- macOS 15에서 다시 설치하거나 업그레이드하면 "Bootstrap failed: 5: Input/output error"로 실패했습니다. `launchctl bootout`이 작업을 지우기 전에 돌아오기 때문입니다. 이제 설치와 제거 스크립트가 작업이 사라질 때까지 기다리고, 설치는 `bootstrap`을 다시 시도합니다.

### 호환성과 한계

- MCP는 기본으로 도구 6개를 알리며, `task_card`는 기억 도구 5개 다음에 옵니다.
- 세션별 열린 카드는 코어 메모리에만 있어서 재시작하면 잊습니다. 다음 프롬프트에서 카드 목록을 다시 보여 줍니다.

- 설치기가 더 이상 없어진 대시보드, 빈 404 주소, 배포되지 않은 Windows 압축 파일을 안내하지 않습니다. Linux 출력은 실제 MCP 주소를 알려 줍니다.
- 예전 contrib 설치기가 실제 `memnest` 실행 파일 경로를 다시 쓰고, pi 확장을 소스에서 다시 빌드하지 않고 배포된 것을 설치합니다.

## [0.2.0] - 2026-08-31

### 추가

- `memnest status`가 대화 수집기의 신호와 마지막 대화 수집을 보여 주고, 신호가 오래됐거나 없으면 경고합니다. 수집 루프가 둘을 상태 파일에 기록하므로 systemd, launchd, 직접 시작한 수집기 모두에서 동작합니다.

### 변경

- `/search`가 `durable_only` 옵션을 받고 `/context` 묶음이 이를 켭니다. 자동 맥락에는 일부러 저장했거나 정리된 기억만 들어갑니다. 원본 대화 AutoLog는 예전 대화를 묻는 명시적 검색에서 그대로 찾을 수 있습니다.

## [0.1.0] - 2026-08-28

첫 공개 릴리스.

### 추가

- e5 임베딩, Tantivy BM25, HNSW 벡터 검색, Reciprocal Rank Fusion, MMR 다양성 순위를 쓰는 로컬 다국어 검색
- 원본인 SQLite. 트랜잭션 색인 작업, 시작 시 복구, 원자적 색인 교체, 손상된 보조 파일 감지, 단독 쓰기 잠금
- 작업공간 범위 기억을 저장, 검색, 수정, 삭제, 확인하는 기억 작업 5개. 기본 `playbook` 컬렉션이 프로젝트 간 회상을 맡습니다.
- `/mcp`의 Streamable HTTP MCP, JSON HTTP API, 같은 작업을 쓰는 stdio MCP 모드
- 프롬프트 시점 맥락용 `memnest hook`과, pi, Claude Code, Codex의 대화를 가려서 수집하는 `memnest watch`
- 구조화된 `record`, `fact`, `rule`, `procedure` 기억 종류. 신뢰도, 출처 ID, 검증 시각, 원자적 `supersedes` 정정 포함
- 백업, 복원, 검증, 상태, 통계, 지원 묶음, 임베딩 미리 받기 명령
- 사용자/시스템 유닛 Linux 서비스 설치, WSL과 Windows 서비스 등록 스크립트
- x86_64와 aarch64용 Linux 릴리스 압축 파일. 각각 SHA-256 체크섬과 함께 배포

### 보안

- 자격 증명처럼 보이는 텍스트는 검색 저장 전에 가립니다.
- 비밀은 별도의 AES-256-GCM 금고를 쓰고, 모델이 쓰는 금고 도구는 `MEMNEST_EXPOSE_SECRET_TOOLS=1`이 아니면 꺼져 있습니다.
- 자동 맥락은 믿을 수 없는 참고 자료로 표시하고, 저장된 마크업은 프롬프트에 넣기 전에 이스케이프합니다.
- 작업공간 식별은 경로에서 만든 해시를 쓰고, 모호한 예전 별칭은 닫힌 쪽으로 실패하며, 프로젝트 거르기는 후보를 만들 때 합니다.
- 새 금고 암호문은 행 정체에 묶이고, 마스터 키는 개인 권한으로 만들며, 백업 복원은 교체 전에 준비한 데이터를 검증합니다.

### 신뢰성

- 확인된 저장은 API가 응답하기 전에 안전하게 기록되고, 중단된 색인 갱신은 시작 때 다시 실행됩니다.
- 정정은 새 원본 대화 조각을 남기지 않고, 대체된 값을 보이는 모든 검색 경로에서 숨깁니다.
- 두 번째 프로세스가 같은 데이터 폴더에 동시에 쓸 수 없습니다.
- 훅이 실패해도 호스트 프롬프트를 막지 않습니다.

### 호환성

- Linux 실행 파일을 돌리는 데 Rust 도구가 필요 없습니다. 임베딩 모델은 첫 저장이나 검색 때, 또는 `memnest --warmup-embedding`으로 직접 내려받습니다.
- Windows와 WSL 스크립트는 사용자가 빌드하거나 준비한 실행 파일을 등록합니다. 이 릴리스는 Windows 실행 파일 압축 파일을 배포하지 않습니다.
