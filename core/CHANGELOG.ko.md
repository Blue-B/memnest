# 변경 이력

[English](CHANGELOG.md) | [한국어](CHANGELOG.ko.md)

`memnest` Rust 엔진의 주요 변경을 기록합니다.

## [출시 전]

### 추가

- 모든 클라이언트용 작업 카드. 카드는 며칠 걸리는 작업의 인계 문서입니다. [작업 카드](../docs/task-cards.ko.md)를 보세요.
  - MCP `task_card` 도구와 `POST /task-card`로 카드를 저장, 목록, 열기, 끝내기, 닫기 합니다.
  - `memnest hook`이 `POST /task-card/hook`을 통해 Claude Code와 Codex의 `SessionStart`와 `UserPromptSubmit`을 처리합니다. 세션 첫 프롬프트에 카드 목록을 보여 주고, 사용자 메시지를 열린 카드에 원문 그대로 기록합니다. 압축 뒤에는 규칙과 사용자 최근 말을 다시 넣습니다.
  - `memnest hook --no-recall`은 자동 회상 없이 작업 카드만 처리합니다.
  - 설치 스크립트가 기본으로 Claude Code(`~/.claude/settings.json`)와 Codex(`~/.codex/hooks.json`)에 이 훅을 넣고, Codex가 `task_card`를 승인 질문 없이 부를 수 있게 합니다. 회상은 여전히 `--autocontext`로 직접 켭니다.

### 호환성과 한계

- MCP는 기본으로 도구 6개를 알리며, `task_card`는 기억 도구 5개 다음에 옵니다.
- 세션별 열린 카드는 코어 메모리에만 있어서 재시작하면 잊습니다. 다음 프롬프트에서 카드 목록을 다시 보여 줍니다.
- Codex는 새 훅을 `/hooks`에서 한 번 신뢰한 뒤에만 실행합니다.

## [0.4.3] - 2026-10-31

### 추가

- Apple Silicon macOS 압축 파일(`aarch64-apple-darwin`). 같은 `install.sh`가 launchd 에이전트로 설치합니다. 코어 CI가 macOS 14 러너에서 설치, 재설치, 재시작, 제거를 확인합니다. 서명이나 공증은 되어 있지 않고, Intel Mac은 여전히 소스로 빌드해야 합니다.

### 수정

- 기본 설치에 더 이상 Python 3.11이 필요하지 않습니다. Python 3.10(Ubuntu 22.04 기본)에서는 Claude Code와 Cursor를 설정하고, 기존 Codex `config.toml`은 `tomllib` 없이 검사할 수 없어서 그대로 둡니다. 직접 넣을 줄은 설치가 출력합니다.

## [0.4.2] - 2026-10-13

### 수정

- x86_64 Linux 압축 파일이 glibc 2.35 이상(Ubuntu 22.04, Debian 12 이후)에서 돌아갑니다. v0.4.0은 Ubuntu 24.04에서 빌드돼서 더 오래된 시스템에서 `GLIBC_2.38 not found`로 시작하지 못했습니다. 이제 Ubuntu 22.04에서 빌드하고, 미리 빌드된 onnxruntime의 C23 `strtol` 계열 참조는 예전 함수로 넘깁니다.
- 실행 파일이 문서에 적은 최저 glibc보다 새 버전을 요구하면 릴리스 작업이 실패합니다.

### 한계

- aarch64 압축 파일은 여전히 glibc 2.39(Ubuntu 24.04 이후)가 필요합니다. 미리 빌드된 onnxruntime이 실행 때 GCC 14의 libstdc++를 필요로 해서, Ubuntu 22.04 라이브러리로는 시작하다 멈췄습니다.
- v0.4.1은 태그만 붙고 aarch64 빌드 실패로 배포되지 않았습니다.

## [0.4.0] - 2026-10-07

### 추가

- 선택 기능인 이름 있는 사용자 bearer 정책. 프로젝트별 정확한 읽기/쓰기 권한, 내용 없는 접근 감사, 보호된 저장소 다시 열기 확인, 프로젝트별 보존 기간을 제공합니다. ID 읽기, 기록, 맥락, 변경, 복원, 금고/통계/감사 경로가 같은 권한 경계를 씁니다.
- 명시적 코드 근거 기록/비교 명령과 제한된 파일 지문. 파일이 바뀌었다고 해결 방법이 무효가 되는 것도, 안 바뀌었다고 검증된 것도 아닙니다.
- 호출자가 보고한 해결 결과, 그리고 `supersedes`를 통한 변경 불가 대체
- 선택 기능 `evidence_only` 근거 선택. 설정한 루프백 Ollama 모델, 제한된 원문 발췌, 정확한 인용 확인을 씁니다. 기본 검색은 여전히 생성 모델을 쓰지 않습니다.
- 이미 휴지통에 있는 기록을 위한 `POST /purge`와, 관리자가 수명 주기 확인을 바로 실행하는 `POST /retention`

### 변경

- 평문 보관 사본은 기본으로 꺼져 있고, `MEMNEST_ARCHIVE=1`로 직접 켭니다. 기존 보관 파일, 백업, 외부 대화 기록, 물리 디스크 사본은 지우지 않습니다.
- 비밀 목록에서 자유 형식 메모를 뺐습니다. 민감한 값이 들어 있을 수 있기 때문입니다. 정책 모드에서 명시적 비밀 조회는 여전히 관리자만 할 수 있습니다.

### 한계

- 한 대의 서버용 팀 제어이며, SSO, SaaS 테넌트 관리, 고가용성, 규제 인증이 아닙니다. 로컬 파일 소유자는 계속 믿을 수 있는 대상입니다.
- 모델이 고른 발췌는 여전히 검증되지 않은 것입니다. 작은 로컬 비교는 더 나은 검색 정확도를 보여 주지 못했습니다. 문서에 적은 자료, 모델 구성, 시간, 이어서 돌린 사실을 보세요.

## [0.3.1] - 2026-09-28

### 수정

- 명시적 `watch --backfill --once --path /original/absolute/path`가 실행 중인 수집기를 되감지 않고 고른 과거 기록을 다시 넣습니다. `--dry-run`은 저장하지 않고 대상 조각을 미리 보여 줍니다. 같은 원본을 다시 넣으면 기존 삭제와 중복 제거 규칙이 적용됩니다. 대상이라고 빠진 것은 아닙니다.
- 한국어와 영문이 섞인 검색에서, 명시한 영문 식별자가 하나도 없는 후보로 이름 일치 결과를 채우지 않습니다. 이름 일치 후보가 없으면 의미 기반 대체 검색은 그대로 동작하며, 이름이 없는 관련 기록은 여전히 놓칠 수 있습니다.

### 추가

- 검색된 사용자 대화 조각 최대 하나에 제한된 `following_id` 힌트. 텍스트에 검색한 이름이 없더라도 클라이언트가 `memory_get`으로 뒤이은 어시스턴트 원문을 읽을 수 있습니다. 검색 결과 순서와 개수는 그대로입니다. 수집 순서는 검증된 답장 관계나 최종 답의 보장이 아닙니다.
- status가 과거 기록이 다 들어왔는지는 확인하지 않았다고 명시합니다.

### 호환성

- 데이터베이스 초기화, 자동 과거 기록 재생, 새 의존성, 추가 생성 모델 호출이 필요 없습니다.
- 릴리스 대상은 계속 Linux x86_64와 aarch64 압축 파일입니다. macOS는 소스만 지원합니다. Windows 빌드는 CI로 확인하지만 Windows 압축 파일은 배포하지 않습니다.

한계와 검증은 [과거 기록 가져오기](../docs/history-import.ko.md), [검색 관련성](../docs/search-relevance.md)(영문), [뒤이은 대화 조각](../docs/following-capture.md)(영문)을 보세요.

## [0.3.0] - 2026-09-15

### 추가

- HTTP와 MCP의 페이지 단위 `memory_get`. 유니코드 위치, 공유 문서 텍스트 예산, 이어 읽기 위치, 같은 프로젝트, 세션, 원본, cwd의 대화 기록 앞뒤 최대 5개 조각을 제공합니다.
- 기록마다 별도의 2048자 예산을 둔 출처 정보. 출처 ID는 최대 16개이고 `provenance_truncated` 표시가 따로 있습니다. 읽는다고 저장된 텍스트와 메타데이터가 바뀌지 않습니다.
- Linux 설치: 클라이언트 찾기, 개인용 정확한 백업, 충돌을 살피는 복원, 사전 요구 확인, 수집기 시작, 임시 저장/검색 왕복. 자동 회상은 계속 직접 켜야 합니다.
- 읽기 전용 `status --diagnose`가 제한된 상태와 MCP 기능 약속을 확인합니다. 상태는 이제 모델을 초기화하지 않고 임베딩 로딩 상태와 색인 대기/재구축 상태를 알려 줍니다.
- 고정된 MemoryBench 어댑터, 작은 한국어 검색 자료, 늘어난 고정 검색 평가, 재현 가능한 독립 클라이언트 데모. 답변 정확도나 제품 비교 벤치마크가 아닙니다.

### 변경

- 결과 자리가 남아 있으면 키워드 결과가 벡터 전용 후보를 모두 밀어내지 않습니다. 흔한 영어 질문 단어는 키워드 근거로 치지 않습니다. 임베딩 모델과 학습된 순위는 바꾸지 않았습니다.
- 영구 삭제한 식별된 대화 이벤트는 내용 없는 삭제 표시를 남겨서, 휴지통 정리나 색인 재구축 뒤 수집기가 다시 넣어도 되살아나지 않습니다.

### 수정

- 없거나 비활성인 `supersedes` 대상은 가려진 내부 오류 500 대신 404나 409를 돌려주며, 현재 기록을 숨기지 않습니다.
- 서버 로그를 stderr에만 써서 stdio MCP의 stdout이 올바른 JSON으로 남습니다.

### 호환성

- 검색은 여전히 결과마다 최대 600자를 돌려주고 검색 전체 텍스트 제한은 없지만, 예전 버전이 버리던 강한 의미 결과가 후보에 들어갈 수 있습니다.
- MCP `memory_get`은 이제 예전의 간단한 머리말과 문서 대신, 이어 읽기와 출처를 포함한 JSON 텍스트를 돌려줍니다. 예전 출력을 파싱하던 곳은 고쳐야 합니다.
- 대화 기록 이웃은 수집 순서를 따르며, 원본의 시간순이나 최종 결정이 아닙니다. 기존 저장소를 지우거나 다시 수집할 필요는 없습니다.
- macOS launchd와 포장 코드는 네이티브 설치, 재시작, 제거가 확인될 때까지 소스만 지원합니다.

v0.2.1 이후 사용자에게 보이는 변경은 [v0.3.0 요약](../docs/next-release.ko.md)을 보세요.

## [0.2.1] - 2026-09-01

### 수정

- 로그인 때 의존 서비스가 시작하지 못할 수 있던 사용자 systemd 순서 순환을 없앴습니다.
- 설치기가 더 이상 없어진 대시보드, 빈 404 주소, 배포되지 않은 Windows 압축 파일을 안내하지 않습니다. Linux 출력은 실제 MCP 주소를 알려 줍니다.
- 예전 contrib 설치기가 실제 `memnest` 실행 파일 경로를 다시 쓰고, pi 확장을 소스에서 다시 빌드하지 않고 배포된 것을 설치합니다.

## [0.2.0] - 2026-08-31

### 추가

- `memnest status`가 대화 수집기의 신호와 마지막 대화 수집을 보여 주고, 신호가 오래됐거나 없으면 경고합니다. 수집 루프가 둘을 상태 파일에 기록하므로 systemd, launchd, 직접 시작한 수집기 모두에서 동작합니다.

### 변경

- `/search`가 `durable_only` 옵션을 받고 `/context` 묶음이 이를 켭니다. 자동 맥락에는 일부러 저장했거나 정리된 기억만 들어갑니다. 원본 대화 AutoLog는 예전 대화를 묻는 명시적 검색에서 그대로 찾을 수 있습니다.

## [0.1.0] - 2026-08-28

첫 공개 릴리스.

### 추가

- e5 임베딩, Tantivy BM25, HNSW 벡터 검색, Reciprocal Rank Fusion, MMR 다양성 순위를 쓰는 로컬 다국어 검색
- 원본인 SQLite. 트랜잭션 색인 작업, 시작 시 복구, 원자적 색인 교체, 손상된 보조 파일 감지, 단독 쓰기 잠금
- 작업공간 범위 기억을 저장, 검색, 수정, 삭제, 확인하는 기억 작업 5개. 기본 `playbook` 컬렉션이 프로젝트 간 회상을 맡습니다.
- `/mcp`의 Streamable HTTP MCP, JSON HTTP API, 같은 작업을 쓰는 stdio MCP 모드
- 프롬프트 시점 맥락용 `memnest hook`과, pi, Claude Code, Codex의 대화를 가려서 수집하는 `memnest watch`
- 구조화된 `record`, `fact`, `rule`, `procedure` 기억 종류. 신뢰도, 출처 ID, 검증 시각, 원자적 `supersedes` 정정 포함
- 백업, 복원, 검증, 상태, 통계, 지원 묶음, 임베딩 미리 받기 명령
- 사용자/시스템 유닛 Linux 서비스 설치, WSL과 Windows 서비스 등록 스크립트
- x86_64와 aarch64용 Linux 릴리스 압축 파일. 각각 SHA-256 체크섬과 함께 배포

### 보안

- 자격 증명처럼 보이는 텍스트는 검색 저장 전에 가립니다.
- 비밀은 별도의 AES-256-GCM 금고를 쓰고, 모델이 쓰는 금고 도구는 `MEMNEST_EXPOSE_SECRET_TOOLS=1`이 아니면 꺼져 있습니다.
- 자동 맥락은 믿을 수 없는 참고 자료로 표시하고, 저장된 마크업은 프롬프트에 넣기 전에 이스케이프합니다.
- 작업공간 식별은 경로에서 만든 해시를 쓰고, 모호한 예전 별칭은 닫힌 쪽으로 실패하며, 프로젝트 거르기는 후보를 만들 때 합니다.
- 새 금고 암호문은 행 정체에 묶이고, 마스터 키는 개인 권한으로 만들며, 백업 복원은 교체 전에 준비한 데이터를 검증합니다.

### 신뢰성

- 확인된 저장은 API가 응답하기 전에 안전하게 기록되고, 중단된 색인 갱신은 시작 때 다시 실행됩니다.
- 정정은 새 원본 대화 조각을 남기지 않고, 대체된 값을 보이는 모든 검색 경로에서 숨깁니다.
- 두 번째 프로세스가 같은 데이터 폴더에 동시에 쓸 수 없습니다.
- 훅이 실패해도 호스트 프롬프트를 막지 않습니다.

### 호환성

- Linux 실행 파일을 돌리는 데 Rust 도구가 필요 없습니다. 임베딩 모델은 첫 저장이나 검색 때, 또는 `memnest --warmup-embedding`으로 직접 내려받습니다.
- Windows와 WSL 스크립트는 사용자가 빌드하거나 준비한 실행 파일을 등록합니다. 이 릴리스는 Windows 실행 파일 압축 파일을 배포하지 않습니다.
