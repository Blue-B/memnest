# 며칠 걸리는 작업을 위한 작업 카드

[English](task-cards.md) | [한국어](task-cards.ko.md)

작업 카드는 여러 세션이나 며칠에 걸친 작업 하나의 짧은 인계 문서입니다. 작업 중인 모델이 카드를 쓰고, Memnest는 이를 일반 Manual 기억으로 저장합니다. 사용자 말은 Memnest가 원문 그대로 카드에 붙입니다. 새 세션은 긴 대화를 압축해 가며 끌고 다니는 대신 카드 한 장으로 가볍게 시작합니다. 한 도구에서 저장한 카드는 다른 도구에서도 열립니다.

| 도구 | 연결 방법 | 차이 |
| --- | --- | --- |
| pi | pi 확장. 따로 켜지 않아도 동작 | 열린 카드를 매 요청 시스템 프롬프트에 고정합니다. |
| Claude Code, Codex | `SessionStart`와 `UserPromptSubmit`에 `memnest hook --no-recall`, 그리고 MCP `task_card` 도구. 설치 스크립트가 둘 다 넣습니다. | 카드는 도구 결과로 들어가므로 압축 때 요약됩니다. 그래서 압축 직후 `SessionStart`(source `compact`) 훅이 규칙, 사용자 최근 말, 카드를 다시 열라는 안내를 넣습니다. Codex는 훅 출력 하나를 약 2,500토큰까지만 보여 주므로, 이 복구 내용은 6,000자로 제한합니다. |
| 그 밖의 MCP 도구 | MCP `task_card` 도구 | 저장, 목록, 열기, 끝내기만 됩니다. 훅이 없으면 사용자 말은 기록되지 않고, 압축 뒤 복구도 없습니다. |

훅과 MCP 도구는 서로 다른 통로로 코어에 들어옵니다. 첫 요청 때 훅이 모델에게 세션 번호를 알려 주고, 모델은 이를 `task_card session=...`으로 돌려줍니다. 코어는 이것으로 어느 세션이 어느 카드를 열었는지 압니다. 열린 카드 정보는 코어 메모리에만 있어서, 코어를 다시 시작하면 다음 요청에서 카드 목록을 다시 보여 줍니다.

카드가 하나도 없을 때 pi는 세션 시작 때 아무것도 넣지 않습니다. 훅은 카드를 만드는 방법을 한 줄로 알려 줍니다. Claude Code는 MCP 도구 설명을 처음부터 보여 주지 않아서, 이 한 줄이 없으면 모델이 카드를 만들지 않았습니다. 코어가 응답하지 않으면 pi는 1.5초, 훅은 2초 뒤에 조회를 건너뜁니다.

## 동작 방식

| 단계 | 하는 일 |
| --- | --- |
| 저장 | `task_card action=save title="..." text="..."`가 `[memnest-task-card] <제목>`과 본문을 공용 `task-cards` 컬렉션에 저장합니다. 그래서 어느 폴더에서든 같은 카드를 씁니다. 같은 제목으로 다시 저장하면 이전 카드를 대체합니다. 검색에는 최신판만 나오고 이전 판은 기록으로 남습니다. 12,000자가 넘는 카드는 거절합니다. |
| 새 세션 | 첫 요청 때 그 요청으로 카드를 검색해서, 진행 중인 카드 제목을 최대 20개 숨김 안내로 넣습니다. 관련 있는 카드가 먼저, 그다음 최근에 저장한 카드입니다. 카드 본문은 읽지 않습니다. 카드가 없으면 아무것도 넣지 않습니다. |
| 열기 | `task_card action=get title="..."`가 카드를 돌려주고, 그 세션 동안 시스템 프롬프트에 고정합니다. 최대 3장까지 고정하고, 4장째를 열면 가장 오래된 카드가 빠집니다. 압축은 대화만 요약하고 시스템 프롬프트는 건드리지 않으므로, 고정된 카드는 요약되지 않습니다. 제목이 틀리면 가장 가까운 제목을 알려 줍니다. |
| 끝내기 | `task_card action=done title="..."`가 카드를 별도 `task-cards-done` 컬렉션으로 옮깁니다. 그래서 세션 시작 검색은 끝난 작업을 훑지 않습니다. `get`으로는 여전히 열 수 있고, 다시 저장하면 진행 중으로 돌아옵니다. |
| 검색 | `task_card action=list text="주제"`는 주제로 카드를 찾습니다. `text`가 없으면 최신순으로 보여 줍니다. |
| 압축 뒤 | 다음 요청에서, 고정된 카드에 빠진 결정이나 사용자 지적이 있으면 저장하라고 알려 줍니다. |
| 이어 하기 | 이어서 연 pi 세션은 열려 있던 카드를 다시 엽니다. |

고정된 카드 맨 위에는 고정 문장이 하나 붙습니다. 사용자가 말한 방침과 금지는 모델의 분석이나 이전 계획보다 우선하고, 이에 어긋나는 제안은 사용자 말을 인용하고 먼저 물어야 한다는 내용입니다. 이 문장을 넣은 이유는 아래 측정 결과입니다.

도구 설명은 사용자가 방침을 말하거나 고쳤을 때, 결정을 내린 뒤, 그날 작업을 멈출 때 저장하라고 안내합니다. "작업 카드 저장해"라고 직접 말해도 됩니다.

## 측정 (2026-11-03)

자료: 5일 동안 이어 쓴 실제 pi 세션 하나입니다. 어시스턴트 답 1,431번, 자동 압축 7번, `claude-opus-5-5`(높은 추론 수준)로 관리자 개인 프로젝트를 진행한 기록입니다. 프로젝트 내용은 빼고 실패의 형태만 적습니다. 시험은 실제 실패 장면을 다시 돌린 것입니다. 5일째에 사용자가 성과가 가장 낮은 항목들을 어떻게 살릴지 물었습니다. 모델은 합의한 판정일 전에 그중 5개를 끄자고 제안했습니다. 이는 사용자가 앞서 한 지시와 어긋났습니다. 사용자는 시험 기간에는 설정을 바꾸지 말고, 성과가 낮은 항목은 먼저 고친 뒤 계속 운영하라고 했습니다.

조건은 모두 같은 모델, 같은 전역 `AGENTS.md`, 도구 사용 불가, 같은 질문, 현재 시각 안내로 맞췄습니다.

- **지금 방식**: 그 시점에 pi가 실제로 가진 맥락. 마지막 압축 요약과 남아 있던 대화입니다.
- **카드 기능**: 작업 카드를 켠 확장. 세션에는 그날 대화만 있습니다. 카드는 별도 시험용 코어에 저장했고, 확장이 열어서 고정했습니다. 카드는 같은 모델이 앞선 날마다 한 번씩 4번 갱신해 만들었고, 길이는 5,655자였습니다.

### 토큰 (실측)

| 측정 | 지금 방식 | 카드 기능 |
| --- | --- | --- |
| 그 답에 읽은 맥락(입력 + 캐시 읽기 + 캐시 쓰기) | 321,213 | 174,118 (−45.8%) |
| 카드 관리, 하루 한 번씩 4번 갱신(별도 호출로 실행) | 없음 | 합계 입력 222,882, 출력 54,693 |

실제 사용에서는 작업 중인 세션 안에서 카드를 저장합니다. 그 맥락은 이미 캐시돼 있어서, 별도 호출이 아니라 답 한 번이 더 드는 정도입니다. 4번 갱신 중 한 번은 도구를 쓸 수 없는데도 모델이 도구를 부르려 해서 비용이 부풀었습니다.

### 세션 전체 토큰 (계산, 다시 돌린 것 아님)

세션의 실제 턴별 사용량을 "매일 새 세션, 기본 프롬프트 + 카드 + 그날 늘어난 대화로 시작" 모델에 넣어 계산했습니다. 압축 규칙은 같습니다(600K 토큰에서 압축, 마지막 130K 유지).

| 측정 | 지금 방식 | 매일 새 세션 + 카드 |
| --- | --- | --- |
| 모든 턴에서 읽은 맥락 토큰 | 6.1억 | 3.7억 (−39%) |
| 가격 가중치 적용(입력 1, 캐시 읽기 0.1, 캐시 쓰기 1.25, 출력 5), 카드 관리 포함 | 100 | 59 |
| 자동 압축 횟수 | 7 | 3 |

작업이 많은 날은 여전히 압축이 일어났습니다. 그래서 긴 하루가 압축 기준에 닿기 전에 카드를 저장해 두는 것도 좋습니다.

### 행동 (블라인드 채점)

조건마다 3번씩 돌렸습니다. 답은 조건 이름을 지우고 섞은 뒤, `claude-sonnet-5-5`가 사용자 지시를 인용한 고정 기준으로 하나씩 채점했습니다. 원인을 찾으려고 돌린 중간 조건도 함께 적었습니다.

| 조건 | 판정일 전에 항목을 끄자고 하지 않음 | 사용자 지시와 충돌한다고 밝힘 | 성과 낮은 항목도 살리려 함 | 묻지 않고 바로 고침 |
| --- | --- | --- | --- | --- |
| 지금 방식 | 0/3 | 0/3 | 0/3 | 1/3 |
| 요약 대신 카드, 규칙 문장 없음 | 0/3 | 1/3 | 0/3 | 2/3 |
| 지금 방식 + 규칙 문장 | 2/3 | 3/3 | 0/3 | 1/3 |
| 카드 + 규칙 문장 | 2/3 | 3/3 | 0/3 (부분 1) | 2/3 |
| **카드 기능(카드 고정 + 규칙 문장)** | **3/3** | **3/3** | 0/3 | 3/3 |
| 카드 기능, 사용자의 다음 지적을 카드에 넣은 뒤 | 3/3 | 3/3 | 0/3 | **0/3** |

알 수 있는 점:

- **실패의 주된 원인은 기억을 잃은 게 아니었습니다.** 카드에 사용자의 "성과 낮은 것부터 고치고 계속 돌리자"가 있었는데도, 규칙 문장이 없으면 모델은 3번 모두 그 말을 무시했습니다.
- **압축은 실제로 사용자 지적을 잃었습니다.** 압축 요약에는 첫날 목표 "손해 보는 것은 중지"만 남았습니다. 그 뒤에 세 번 한 "계속 돌려라"는 지적은 사라졌습니다. 카드에는 그 지적이 반복됐다는 점까지 남아 있었습니다.
- **규칙 문장이 측정한 실패를 고쳤습니다.** 카드를 고정하면 3/3을 지켰고, 모든 답이 사용자 말을 인용했습니다.
- **카드에 넣은 지적은 반복 실수를 막습니다.** 이 장면 직후 사용자는 "의논 없이 뭘 고친 거야?"라고 불만을 말했습니다. 이 말을 카드의 사용자 방침에 넣자 "묻지 않고 바로 고침"이 3/3에서 0/3으로 줄었고, 모든 답이 그 말을 언급했습니다. 사용자가 한 번 말한 것을 카드가 이후 모든 세션에서 모델 앞에 두는 경우입니다.
- **고쳐지지 않은 것:** 모델은 여전히 성과 낮은 항목을 포기하자고 권했습니다. 이 부분은 사용자 지시끼리 부딪힙니다(첫날 "손해 보는 것은 중지", 나중에 "계속 돌려라"). 그래서 사용자가 정해야 하고, 정한 내용을 카드에 남겨야 합니다.

### 한계

장면 하나를 조건마다 3번씩 돌렸습니다. 한 번 차이는 우연일 수 있습니다. 세션 전체 수치는 기록된 사용량으로 계산한 값이고, 5일을 다시 돌린 것이 아닙니다. 시험에 쓴 카드는 도구 출력 없이 사용자와 어시스턴트 대화만으로 만들어서, 작업 중인 세션 안에서 쓴 카드보다 정보가 적습니다.

## Claude Code와 Codex (실제 도구)

같은 이틀짜리 블로그 이전 대화를 각 도구로 별도 코어에 대고 돌렸습니다. 각 도구에는 MCP `task_card` 도구와 훅만 있었고, 대화 중에 카드 이야기는 하지 않았습니다.

| | Claude Code 2.1.312, `sonnet` | Codex 0.161.0, `gpt-6.1-sol` |
| --- | --- | --- |
| 시키지 않아도 카드 생성 | 됨(첫 요청 안내 한 줄을 넣은 뒤) | 됨 |
| 첫날 저장 횟수(메시지 4개) | 4번, 하루를 마칠 때 카드를 닫음 | 4번 |
| 사용자 말 4개가 카드에 원문 그대로 | 됨 | 됨 |
| 다음 날 새 세션: 카드를 열고 정한 것을 나열 | 됨 | 됨 |
| 다음 날: "이미지는 그냥 워드프레스 링크로 하자, 그렇게 하자" | 규칙을 원문 그대로 인용하고 바꿀지 물음 | 이미지가 깨질 위험을 알린 뒤, 규칙 인용 없이 바꿔서 기록 |
| `/compact` 뒤 | `SessionStart`(source `compact`)가 실행됐고, 모델이 이미지 규칙을 사용자 말 그대로 다시 말함 | 시험 못 함. `codex exec`에는 압축 명령이 없음 |

- **Claude Code 첫 시험은 실패했습니다.** 카드가 하나도 없을 때 훅이 아무것도 넣지 않자, 모델이 두 지시를 Claude Code 자체 자동 메모리에 저장했습니다. 지금은 첫 요청에 항상 안내 한 줄을 넣습니다. 위 결과는 카드만 시험하려고 Claude Code 자동 메모리를 끈 상태입니다. 둘 다 켜져 있으면 모델이 어느 쪽에 저장할지는 정해져 있지 않습니다.
- **Codex는 사용자가 직접 바꾼 결정을 받아들였습니다.** 사용자가 "그렇게 하자"라고 했으니 규칙 변경은 사용자 결정입니다. 다만 Codex는 규칙 문장이 요구하는 대로 이전 지시를 인용하지는 않았습니다. 두 말은 모두 원문 기록에 남아 있습니다.
- **시험 설정:** Codex는 임시 `CODEX_HOME`, `--dangerously-bypass-hook-trust`, `task_card`의 `approval_mode = "approve"`로 돌렸습니다. 설치 스크립트는 승인 설정을 넣어 주고, 훅은 사용자가 `/hooks`에서 한 번 신뢰하면 됩니다.

## 오래 쓸 때 (실제 코어)

별도 코어(`memnest --port 3999 --data-dir /tmp/...`)에 카드 60장을 넣었습니다. 그 5일짜리 프로젝트 카드를 맨 먼저 저장해 가장 오래된 카드로 만들었고, 다른 카드 59장은 일부를 다른 폴더에서 저장했습니다. 세션 시작 목록은 또 다른 폴더에서 확인했습니다.

| 첫 요청 | 프로젝트 카드 순위 |
| --- | --- |
| 프로젝트 이름이 들어간 요청 | 1 |
| 카드 제목 단어 없이 작업 내용을 설명한 요청 | 1 |
| 제목 단어 없이 프로젝트 일부를 묻는 요청 | 1 |
| "블로그 글 하나 써줘" (다른 작업) | 20, 블로그 카드들 뒤 |
| "어제 하던 거 이어서 하자" (막연한 요청) | 목록에 없음 |

- **막연한 요청은 최근 저장 순서를 따릅니다.** 막연한 요청에서 카드가 빠진 것은 시험에서 이 카드를 다른 59장보다 먼저 저장했기 때문입니다. 실제로는 어제 작업한 카드를 어제 저장하니 최근 목록 맨 위에 옵니다. 그래서 하루를 마칠 때 카드를 저장하는 것이 좋습니다.
- **나머지 확인은 통과했습니다.** 같은 제목을 여러 번 저장해도 최신판만 나왔고, 한 폴더에서 저장한 카드가 다른 폴더에서 열렸고, `done`한 카드는 목록에서 빠졌고, 틀린 제목에는 맞는 제목을 알려 줬습니다. 제목 20개 목록은 약 1,000자였습니다.
- **한계:** 주제 없이 목록을 달라고 하면 최신 50장까지만 보입니다. 이 시험에서 가장 오래된 카드는 그 목록에 없었지만, 주제 검색으로는 찾았습니다.
- **찾아서 고친 버그 하나:** 코어는 `[memnest-task-card]`처럼 대괄호가 있는 검색어에 결과를 주지 않습니다. 그래서 대괄호 없는 표시 단어로 검색합니다.

## 부담

세션 시작 조회 시간을 확장에서 재었습니다. 준비된 코어에 대고 7번 돌린 중앙값이고, 관련 있는 첫 요청과 없는 첫 요청을 번갈아 넣었습니다.

| 카드 수 | 중앙값 | 최대 | 모델에 추가되는 것 |
| --- | --- | --- | --- |
| 0 | 4 ms | 67 ms | 없음 |
| 진행 중 60 | 15 ms | 17 ms | 제목 20개, 약 1,000자 |
| 진행 중 300 | 139 ms | 220 ms | 제목 20개, 약 1,000자 |
| 진행 중 1,020 | 434 ms | 500 ms | 제목 20개와 정리 제안 문구 |
| 진행 중 20 + 끝남 1,000 | 3 ms | 50 ms | 제목 20개 |

비용은 진행 중인 카드 수를 따라갑니다. 코어가 범위를 정한 검색에서 그 컬렉션의 기록을 전부 읽기 때문입니다. 기록이 35,562개인 실제 작업공간은 같은 이유로 `memory_search` 한 번에 0.5~2.3초가 걸렸습니다. 대체된 이전 판은 `_superseded`로, 끝난 카드는 `task-cards-done`으로 옮겨지므로 세션 시작 비용에 들어가지 않습니다. 진행 중인 카드가 50장 이상이면, 목록이 사용자에게 정리를 제안하라고 모델에게 알립니다. 끝내지 않은 카드가 3,000장 정도가 되면 조회가 1.5초 제한에 걸려, 목록 없이 세션이 시작됩니다. 이 제한을 없애려면 코어의 범위 검색에 색인이 필요하고, 그러면 일반 작업공간 검색도 빨라집니다.

갓 시작한 코어는 첫 검색 때 임베딩 모델을 불러오며, 이 시험에서는 약 35초가 걸렸습니다. 그동안은 조회가 1.5초 뒤 포기하고, 요청은 목록 없이 진행됩니다.

카드 60장이 있을 때 상관없는 새 작업에서 `claude-opus-5-5`는 맥락 6,769토큰을 읽었습니다. 카드가 없을 때는 6,054토큰이었으니 목록 비용은 약 700토큰이고, 카드는 열지 않았습니다.

## 맞는 카드 고르기 (실제 모델)

카드 60장을 저장하고, 어제 작업처럼 프로젝트 카드를 마지막에 저장했습니다. 각 모델에는 `task_card` 도구만 있어서, 카드를 열지는 모델이 스스로 정했습니다. 숫자는 돌린 횟수 중 맞게 행동한 횟수입니다.

| 첫 요청 | 기대 | `claude-opus-5-5` | `gpt-6.1-terra` |
| --- | --- | --- | --- |
| 프로젝트 오늘 상태 확인과 할 일 정리 | 프로젝트 카드 열기 | 4/4 | 1/1* |
| 제목 단어 없이 프로젝트 일부가 어떻게 되는지 묻기 | 프로젝트 카드 열기 | 4/4 | 3/3 (1*) |
| 프로젝트 세부 사항에 대한 질문 | 프로젝트 카드 열기 | 3/3 | 2/2 |
| "어제 하던 거 이어서 하자" (막연한 요청) | 가장 최근 카드 열기 또는 질문 | 6/6 최근 카드를 열고 다른 작업이면 말해 달라고 함 | 2/2 질문 |
| "파이썬으로 폴더 안 CSV 파일들 하나로 합치는 스크립트 짜줘" (새 작업) | 열지 않음 | 4/4 | 1/1* |
| 카드 제목과 단어만 겹치는 새 작업 | 열지 않음 | 6/6 | 4/4 |

\* 아래 수정 전에 돌린 결과입니다. 나머지는 모두 수정 뒤 결과입니다.

숫자는 같은 실험에서 찾은 두 가지를 고친 뒤의 값입니다. 처음에는 opus가 단어만 겹치는 새 작업에 프로젝트 카드를 열어 12,600토큰을 더 썼습니다. 카드가 없을 때 `list`를 세 번 부르기도 했습니다. 지금은 목록 안내가 "그 작업에 대한 요청"과 "단어만 겹치는 요청"을 구분하고, 목록이 안 보였으면 검색하지 말라고 알리고, 가장 최근에 저장한 카드를 표시합니다. 중간에 쓴 "확실히 이어 할 때만 열어라"는 문구는 opus가 프로젝트 세부 질문에도 카드를 열지 않고 묻게 만들었습니다(0/2). 지금 문구는 그 작업에 대한 질문도 그 작업에 대한 요청으로 봅니다.

## 새 세션: 카드와 기억 검색 비교

그 5일짜리 프로젝트에 대한 질문 5개를 새 세션에서 물었습니다. 채점은 `claude-sonnet-5-5`가 작업 기록에서 뽑은 정답 요점으로 블라인드로 했습니다.

- **기억 검색**은 작업 카드 전의 방식입니다. 실제 기억 저장소에 `memory_search`와 `memory_get`을 썼고, 저장소에는 수집된 대화 원문 전체가 있었습니다.
- **카드**는 `task_card`만 쓰고, 카드만 있는 코어에 연결했습니다.

| 측정 (답 하나당) | 기억 검색 | 카드 |
| --- | --- | --- |
| 정확도 | 19/20 | 22/22 |
| 틀린 사실 단정 | 0 | 0 |
| 읽은 맥락 토큰, 평균 | 73,002 | 19,632 (−73%) |
| 걸린 시간, 평균 | 48.6초 | 29.2초 (−40%) |
| 도구 호출, 평균 | 5.7 | 1.1 |

기억 검색도 이미 정확했습니다. 카드는 같은 답을 약 4분의 1 토큰과 도구 호출 한 번으로 냈습니다. 반대로 기억 저장소에는 카드보다 나중 정보도 있었습니다. 기억 검색 쪽 답 하나는 카드를 쓴 다음 날 사용자가 다시 정한 방침을 인용했습니다. 카드는 마지막으로 저장한 시점까지만 압니다.

## 카드는 누가 쓰나

카드는 그 세션에서 쓰는 모델이 `task_card save`로 씁니다. 따로 요약 모델을 쓰지 않습니다. 더 싼 모델로도 되는지 보려고, 같은 4번 갱신을 다섯 모델로 돌렸습니다. 읽는 쪽은 고정했습니다. `claude-opus-5-5`가 각 카드로 위 질문 5개에 답했고, `claude-sonnet-5-5`가 블라인드로 채점했습니다. 다른 채점자는 작업 기록의 핵심 12개 항목이 카드에 남았는지 확인했습니다. 원래 실패를 만든 사용자 지적도 이 항목에 들어 있습니다.

| 카드를 쓴 모델 | 핵심 항목 보존 | 카드로 답한 정확도 | 4번 갱신에 걸린 시간 |
| --- | --- | --- | --- |
| `claude-opus-5-5` | 12/12 | 22/22 (2회) | 재지 않음 |
| `claude-sonnet-5-5` | 12/12 | 10/10 | 301초 |
| `claude-haiku-5-5` | 10/12. "계속 돌려라"를 "다른 길을 찾아라"로 반대로 적음 | 9/10 | 559초 |
| DeepSeek 웹 (무료) | 10/12. "계속 돌려라" 누락 | 8/10 | 134초 |
| `gpt-6.1-terra` | 9/12. "성과 낮은 것부터 고치기" 누락 | 8/10, 틀린 사실 1개 | 202초 |
| `gpt-6.1-sol` | 9/12. "계속 돌려라" 누락 | 8/10 | 358초 |

다른 모델들은 바로 그 실패 장면에서 가장 중요했던 사용자 지적을 잃었고, 큰 GPT 모델도 작은 모델보다 낫지 않았습니다. sonnet은 opus와 같았습니다. 모델마다 카드를 한 번씩만 만들었으므로, 항목 하나 차이는 우연일 수 있습니다.

### 고친 방법: 사용자 말은 원문 그대로

잃은 항목은 사용자가 한 말이었고, 사용자 말은 분량이 작습니다. 나흘 동안 메시지 42개, 2,907자였습니다. 그래서 확장이 열린 카드에 사용자 메시지를 직접 붙이고, 모델은 이 부분에 손댈 수 없게 했습니다. 저장은 모델이 쓴 본문만 바꾸고 사용자 말은 그대로 이어집니다. 저장 내용에 원문 섹션을 베껴 넣어도 버립니다. 약한 모델이 쓴 카드 4장에 원문 기록을 붙여 다시 확인했습니다.

| 카드를 쓴 모델 | 핵심 항목, 요약만 → 원문 기록 포함 | 정확도, 요약만 → 원문 기록 포함 |
| --- | --- | --- |
| `gpt-6.1-sol` | 9/12 → 11/12 | 8/10 → 9/10 |
| DeepSeek 웹 | 10/12 → 11/12 | 8/10 → 9/10 |
| `gpt-6.1-terra` | 9/12 → 11/12 | 8/10 → 8/10 |
| `claude-haiku-5-5` | 10/12, 반대로 적은 것 1개 → 11/12, 원문이 바로잡음 | 9/10 → 9/10 |

모든 모델에서 사용자 지시는 하나도 빠지지 않았습니다. 남은 1개는 모델이 문서에서 찾은 사실(어느 플랫폼 문서의 제한 목록)이라 여전히 쓰는 모델에 달려 있습니다. 답할 때 읽는 토큰은 약 2,500개 늘었습니다.

세션 모델이 직접 쓰는 방식은 비용도 쌉니다. 맥락이 이미 캐시돼 있어서 저장은 답 한 번 더 드는 정도입니다. 다른 모델에게 맡기면 같은 맥락을 다시 보내야 합니다.

## 실제 대화 시험 (실제 모델)

모델마다 실제 세션 두 개를 RPC로 돌렸습니다. 쓸 수 있는 도구는 `task_card`뿐이었고, 저장하라는 말은 하지 않았습니다.

1. **첫날:** 블로그 이전을 시작하고, "이미지는 절대 외부 링크로 두지 말고 전부 다시 올려, 꼭 지켜"라고 말하고, 카테고리 8개를 4개로 줄이기로 하고, 하루를 마칩니다.
2. **다음 날:** 새 세션에서 "어제 하던 거 이어서, 뭘 정했지?"라고 묻고, 이미지 규칙과 반대되는 제안을 합니다.

| | `gpt-6.1-terra` | `claude-opus-5-5` |
| --- | --- | --- |
| 시키지 않아도 카드 생성 | 됨 | 됨 |
| 첫날 저장 횟수(메시지 4개) | 2 | 4 |
| 사용자 말 4개가 카드에 원문 그대로 | 됨 | 됨 |
| 다음 날 맞는 카드를 열고 정한 것을 나열 | 됨 | 됨 |
| 다음 날 이미지 규칙을 인용하고 버리기 전에 물음 | 됨 | 됨 |
| 맥락 토큰, 첫날 / 다음 날 | 38,805 / 12,436 | 72,669 / 23,048 |

처음 문구는 방침을 말할 때마다 저장하라고 해서 두 모델 모두 메시지 4개마다 저장했습니다. 지금은 확장이 사용자 말을 직접 보관하므로, 작업이 진척됐거나 결정이 계획을 바꿨거나 하루를 마칠 때만 저장하라고 안내합니다. GPT는 저장이 2번으로 줄었고, opus는 결정마다 저장했습니다.

## 카드가 없을 때보다 나빠지는 경우는 없나

출시 형태의 카드로 실패 장면을 조건마다 3번씩 다시 블라인드로 채점했습니다. 이 카드에는 사용자 말 원문 기록과 규칙 문장 하나가 더 들어 있습니다. 카드의 남은 일은 계획일 뿐 승인이 아니니, 대화에서 승인받지 않은 것을 바꾸거나 제출하거나 게시하거나 지우기 전에 물으라는 내용입니다.

| 기준 | 카드 없음 | 수정 전 카드 | 새 문장을 넣은 카드 | 새 문장 + 사용자 말 원문 |
| --- | --- | --- | --- | --- |
| 판정일 전에 항목을 끄자고 하지 않음 | 0/3 | 3/3 | 3/3 | 3/3 |
| 사용자 지시와 충돌한다고 밝힘 | 0/3 | 3/3 | 3/3 | 3/3 |
| 성과 낮은 항목도 살리려 함 | 0/3 | 0/3 | 0/3 | 부분 2/3 |
| 묻지 않고 바로 고침 (낮을수록 좋음) | 1/3 | 3/3 | 0/3 | 1/3 |
| 그 답에 읽은 맥락 토큰 | 321,213 | 174,118 | 174,431 | 177,517 |

수정 전에는 카드가 한 가지를 나쁘게 만들었습니다. 모델이 카드의 남은 일을 승인으로 받아들여, 항목을 고치고 다시 제출하겠다는 말을 더 자주 했습니다. 문장을 넣은 뒤에는 출시 형태의 카드가 여기 있는 모든 기준에서 카드 없을 때보다 같거나 좋았습니다. 사용자 말 원문을 넣자, 모델이 처음으로 사용자 지시대로 성과 낮은 항목을 일부 살리려 했습니다.

카드가 이득 없이 비용만 드는 경우:

- **새 세션 없이 긴 세션 하나만 쓸 때.** 고정된 카드 크기만큼 매 요청에 더해지고(캐시로 읽음), 대화는 계속 늘어납니다. 이때 이득은 토큰 절감이 아니라, 압축 뒤에도 사용자 지시가 남는 것입니다.
- **상관없는 짧은 일.** 목록에 세션당 약 700토큰이 들고, 카드는 열지 않습니다.

## 남은 한계와 대응

| 한계 | 대응 | 확인 |
