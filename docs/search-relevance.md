# 검색 결과의 불필요한 채우기 줄이기

## 변경

한국어 질문에 영문 이름이 명시된 경우, 기존 검색 후보 중 그 이름과 맞는 기록이
있다면 이름이 전혀 없는 후보로 나머지 결과 수를 채우지 않는다.

- 기존 한국어 조사 처리와 영어 불용어 처리를 재사용한다.
- 영문 이름은 대소문자를 무시하되 단어 경계를 확인한다. 예를 들어 `pi`를
  `API`나 `pipeline` 안에서 찾았다고 인정하지 않는다. `task도`는 `task`와 맞는다.
- 반환되는 600자 발췌가 아니라 전체 기록에서 확인한다.
- 이름과 맞는 후보가 없으면 기존 의미 검색 동작을 유지한다.
- 오래됐다는 이유나 최종 점수가 음수라는 이유로 제거하지 않는다.
- 새 모델, 추가 임베딩 요청, 생성형 AI 호출과 새 의존성은 없다.

공통 검색 경로에 적용하므로 HTTP, MCP와 같은 경로를 쓰는 문맥 조회에 적용된다.
`n_results`는 최대 개수이며, 결과를 반드시 그 수만큼 채우지는 않는다.

이것은 완전한 관련성 판정이 아니다. 같은 이름을 언급하는 무관한 기록은 남을 수
있고, 이름 없이 같은 대상을 설명한 기록은 이름이 맞는 후보가 있을 때 제외될 수 있다.
한국어만 쓰거나 영어만 쓰는 검색은 이 필터로 바꾸지 않는다.

v0.3.1에서는 검색된 질문에 답변 출처 ID를 안내해, 같은 대화의 설명을
이름 없이도 읽는 경로를 보완했다. 범위와 한계는 [후속 기록 안내](following-capture.md)를
참고한다. 후속 출처 안내는 아래 이름 필터 검증과 별도로 시험했다.

## 검증

구현 전에 실제 회상 질문 2개, 기존 실기록 질문 12개와 검사할 기록을 고정했다.
격리된 같은 DB와 같은 질문으로 이전/수정 실행 파일을 각각 한 번 실행했다.
생성형 모델에 답변을 만들게 한 실험은 아니다.

| 항목 | 이전 | 수정 후 |
|---|---:|---:|
| 회상 질문에서 사전에 확인한 무관한 결과 | 5개 | 0개 |
| 두 질문의 필수 회상 시작점 유지 | 2개 | 2개 |
| 기존 12개 질문의 지정 기록이 첫 5개에 존재 | 9개 | 10개 |
| 기존에 찾았던 지정 기록 보존 | 9개 | 9개 |
| 14개 질문의 총 반환 기록 | 66개 | 54개 |
| 직렬화한 MCP 응답 글자 수 합계 | 45,431자 | 38,577자 |

응답 글자 수 합계는 **15.1% 감소**했다. 다만 네 질문은 응답이 더 길어졌다.
실제 청구 토큰, 전체 대화 비용이나 후속 원문 조회 비용의 절감률은 측정하지 않았다.

한 회상 질문은 5개 결과 대신 관련된 과거 질문 1개를 반환했다. 당시 답변은 여전히
주변 대화 조회로 읽어야 한다. 첫 검색에서 원문 답까지 자동으로 해결한 것은 아니다.
두 회상 질문은 같은 필요를 다르게 표현한 사례이며, 전체 사용자나 모든 언어의
검색 정확도를 대표하지 않는다.

회귀 검사는 `core/src/server/api.rs`에 있다. 다음을 확인한다.

- 식별자 경계와 한국어 조사 처리.
- 적합한 이름이 없을 때 의미 검색 유지.
- 공통 질문 단어만 겹친 기록으로 결과를 채우지 않음.
- 이름이 발췌 범위 뒤에 있어도 인정.
- 오래된 음수 점수 기록도 이름이 맞으면 유지.

push할 변경만 따로 추출한 소스에서도 라이브러리 검사 119개, 실행 파일 검사 5개와
배포용 빌드가 통과했다. 그 실행 파일로 위 14개 질문의 결과 목록과 응답 길이가
같음을 확인했고, 실제 CLI 가져오기 및 삭제·재시작·색인 재구성 검사도 통과했다.

개인 질문, 대화 원문, 기록 ID, 인증 정보와 검증 DB는 저장소에 포함하지 않는다.
