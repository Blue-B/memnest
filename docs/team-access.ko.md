# 팀 권한, 감사, 보존 정책

[English](team-access.md) | [한국어](team-access.ko.md)

이 기능은 한 대의 서버에서 쓰는 선택적 팀 제어입니다. SSO 서비스, 여러 지역 플랫폼, 규제 인증이 아닙니다. 믿을 수 있는 컴퓨터 관리자는 데이터 파일을 읽을 수 있습니다. 원격 접속에는 요청 수 제한이 있는 TLS 리버스 프록시를 쓰고, 서비스 포트를 인터넷에 직접 열지 마세요.

## 이름 있는 사용자

`MEMNEST_ACCESS_POLICY`에 운영자가 관리하는 JSON 파일을 지정합니다. 이 파일에는 이름 있는 사용자(principal), 엔트로피가 높은 bearer 토큰의 SHA-256 해시, 프로젝트별 읽기/쓰기 권한, 선택 사항인 프로젝트별 보존 일수가 들어갑니다. 서버는 접속을 받기 전에 정책 전체를 검사합니다. 관리자는 한 명 이상 있어야 합니다. 쓰기 권한은 읽기 권한도 함께 있어야 하고, 와일드카드 권한은 해석하지 않습니다.

자격 증명을 화면에 출력하지 않고 개인용 시작 정책을 만듭니다.

```sh
python3 scripts/create-access-policy.py --out /private/new-policy \
  --read company-project --write company-project
```

새 폴더는 미리 있으면 안 됩니다. `policy.json`에는 토큰 원문이 아니라 해시가 들어갑니다. `admin.env`와 `client.env`에는 생성된 자격 증명이 들어 있고 권한은 0600입니다. 비공개로 보관하고, 승인된 자격 증명 전달 방법으로만 넘기고, 커밋하지 마세요. 자동으로 설치되거나 읽히지 않습니다. 정책을 검토하고, 해당 환경 변수를 서비스와 클라이언트에 넣은 뒤, 변경이나 토큰 폐기를 적용하려면 서비스를 다시 시작합니다.

`MEMNEST_TOKEN`은 여전히 클라이언트의 bearer 헤더 값으로 쓰입니다. 정책 모드에서는 정책에 있는 토큰만 인증되고, 예전 전역 토큰으로 우회할 수 없습니다. 정책이 없으면 원래의 "믿을 수 있는 로컬 소유자" 모드가 그대로 동작합니다.

Unix에서 정책 모드는 데이터 폴더 자체가 소유자 전용(권한 0700)이어야 합니다. 저장소를 한 번 정책 모드로 열면 표시가 남아서, `MEMNEST_ACCESS_POLICY`를 지우는 것만으로는 이 버전이 다시 열지 않습니다. 이 표시를 모르는 예전 실행 파일로 보호된 저장소를 열지 마세요. 되돌리려면 이 보호를 무시하는 대신, 검토한 이전 실행 파일과 설정, 그리고 맞는 백업을 복원해야 합니다.

## 범위 적용

권한은 저장, 검색, ID로 직접 조회, 수정, 프로젝트 이동, 삭제, 복원, 영구 논리 삭제에 적용됩니다. HTTP와 MCP 모두 같은 검사를 거칩니다. `project=all`은 그 사용자가 읽을 수 있는 프로젝트만 검색합니다. 작업공간 기준 검색이라도 권한 없는 `playbook`이나 예전 별칭을 결과에 끌어올 수 없습니다.

ID를 안다고 접근할 수 있는 것은 아닙니다. 접근할 수 없는 ID를 읽으면 일반적인 "찾을 수 없음" 응답을 줍니다. 여러 ID를 한 번에 다룰 때는 권한 실패를 먼저 확인한 뒤에 어느 것도 바꾸지 않습니다. 다만 그 뒤에 생길 수 있는 모든 저장 실패까지 되돌린다고 주장하지는 않습니다.

새로 숨겨지는 기록에는 서버가 쓴 권한 범위가 남습니다. 삭제된 대체 기록을 복원하면 대체된 상태로 남아서, 오래된 정보가 다시 활성화되지 않습니다. 믿을 만한 범위 정보가 없는 예전 숨김 기록은 관리자만 볼 수 있습니다. 이름이나 호출자가 넣은 메타데이터로 소유자를 추측하지 마세요.

전역 비밀 금고, 전역 통계, 감사 화면은 관리자만 씁니다. 로컬 stdio/라이브러리 호출자는 네트워크 사용자 격리가 아니라 "믿을 수 있는 파일 시스템 소유자" 규칙을 따릅니다. 믿을 수 없는 에이전트는 서비스 소유자의 OS 계정 밖에서 실행하세요. 데이터베이스를 이미 읽을 수 있는 사람은 API 토큰으로 막을 수 없습니다.

## 감사

`GET /audit`은 최신 이벤트 200개를 보여 주는 관리자 화면입니다. 전체 기록은 SQLite의 `access_events` 테이블에 있고, 일반 데이터베이스 백업에 포함됩니다. 요청과 기억 접근, 변경을 인증된 사용자 ID에 연결해 기록합니다. 검색어, 기억 본문, 응답 본문, bearer 값, 비밀 이름은 남기지 않습니다.

요청 시도는 처리 전에 기록합니다. 감사 기록에 실패하면 접근을 막습니다. 완료 기록 실패는 변경이 이미 반영된 뒤에 생길 수 있으므로, 실패 응답이 변경이 취소됐다는 증거는 아닙니다. 다시 시도하기 전에 처음 이벤트와 작업 상태를 확인하세요. 이것은 운영자가 관리하는 감사 기록이며, 위변조를 막는 외부 원장이 아닙니다.

## 보존과 삭제

정책에 `retention_days` 항목을 넣습니다. 예: `"retention_days": {"company-project": 90}`. 값은 1~3650일입니다. 이 최대 보관 기간은 원래 사건 날짜를 추정한 값이 아니라 기록에 저장된 생성 시각을 기준으로 하며, 그 프로젝트에서는 고정, 중요도, 종류에 따른 예외보다 우선합니다. 설정하지 않은 프로젝트는 기존의 "보존 우선" 정책을 따릅니다. 범위를 알 수 없는 예전 숨김 기록은 소유자를 추측하지 말고 관리자가 검토해야 합니다.

기간이 지난 기록은 먼저 휴지통으로 갑니다. 휴지통 기본 보관은 30일이고, `MEMNEST_TRASH_RETENTION_DAYS`로 0~3650을 정할 수 있습니다. 0이면 다음 정리 때 휴지통을 비울 수 있습니다. 관리자는 `POST /retention`으로 정리를 바로 실행할 수 있습니다.

평문 보관 사본은 이제 기본으로 꺼져 있습니다. `MEMNEST_ARCHIVE=1`로 직접 켤 수 있고, 이 설정을 바꿔도 기존 보관 파일은 지워지지 않습니다.

`POST /purge`는 `{"ids":["<받은 기억 ID>"]}`를 받아, 이미 휴지통에 있는 기록을 운영 데이터베이스와 파생 색인에서 영구히 지웁니다. 활성 기록은 충돌 응답을 주므로 먼저 일반 삭제를 해야 합니다. 그 프로젝트의 쓰기 권한이 필요합니다. 대화 기록에는 삭제 표시가 남아서 같은 이벤트를 다시 수집해도 되살아나지 않습니다.

영구 삭제는 물리적인 안전 삭제가 아닙니다. 예전 보관 파일, 백업, 원래 대화 기록, 예전 파생 사본, 이미 다른 모델에 보낸 텍스트는 지우지 않습니다. SSD와 WAL 동작, 운영자가 가진 사본은 조직 차원의 삭제 계획이 필요합니다. 응답은 모든 사본이 사라졌다고 주장하지 않고 이 한계를 밝힙니다.

## 모델 경로 제한

pi에서 `MEMNEST_ALLOWED_MODEL_PROVIDERS`는 쉼표로 구분한 허용 목록입니다(선택 사항). 예를 들어 믿을 수 있는 환경에서는 등록된 로컬 제공자만 허용할 수 있습니다. 허용되지 않았거나 알 수 없는 모델로 작업 중이면, 검색 요청을 보내기 전에 새 검색, 기억 읽기, 자격 증명 읽기, 자동 회상을 막습니다.

이 검사는 런타임이 밝힌 제공자 ID만 봅니다. 프록시가 실제로 로컬에 머무는지 증명하거나, 다른 API 클라이언트를 막거나, 권한 있는 사용자가 데이터를 복사하는 것을 막거나, 예전 대화 기록을 지우지는 못합니다. 데이터와 모델의 경계를 바꿀 때는 새 세션을 시작하고, 실제 외부 전송은 믿을 수 있는 게이트웨이에서 막으세요. 로컬에 저장한다고 해서 검색 결과가 클라우드 모델에 가지 않는 것은 아닙니다.

코어의 선택 기능인 `evidence_only` 검색은 `MEMNEST_EVIDENCE_URL`로 설정한, 자격 증명 없는 루프백 Ollama 주소만 씁니다. 클라우드 추론 주소는 허용하지 않습니다. 모델이 고른 발췌는 사실 검증이 아닙니다.

## 실행 검사

```sh
python3 scripts/test-access-policy.py
(cd pi-extension && npm run build && node test/model-policy.mjs)
```

격리된 테스트는 실제 HTTP/MCP 읽기와 변경, 위조한 범위 메타데이터, 다른 프로젝트 ID와 묶음 요청, 기록 복원, 비밀/통계/감사 제한, 내용 없는 사용자 기록, 보호된 저장소 재시작, 고정 기록 만료, 영구 삭제, 대화 재수집을 확인합니다. 운영 저장소를 노출하거나 지우지 않습니다.
