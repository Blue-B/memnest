# 다음 출시 변경 요약

<!-- markdownlint-disable MD013 -->

이 문서는 아직 발행하지 않은 변경의 요약입니다. 비교 기준은 공개된 코어 `v0.2.1`과 pi 확장 `v0.2.0`입니다. 기존에 로컬에서 작업했던 설치 개선과 원문 조회 기능도 함께 포함했습니다. 버전 번호, 태그, 배포는 아직 변경하지 않았습니다.

## 가장 크게 달라지는 점

**기억을 저장하고 필요할 때 찾는 기능은 유지하되, 요청하지 않은 자동 주입은 기본으로 끕니다.** 긴 기록은 필요한 부분만 이어 읽고, 어디서 나온 기억인지 확인할 수 있습니다.

| 항목 | 이전 출시 | 다음 출시 변경 |
| --- | --- | --- |
| pi 자동 회상 | 일정 길이 이상의 요청에서 기본으로 기억을 검색하고 조건에 맞으면 주입 | 기본 꺼짐. 사용자가 명시적으로 켰을 때만 검색하고 주입 |
| 자동 주입 내용 확인 | 짧게 잘린 내용과 점수만 보고 판단 | 기억 ID, 프로젝트, 생성 시각을 함께 표시. ID로 원문 확인 가능 |
| 불완전한 검색 결과 | ID가 없어도 허용하고 점수가 없으면 높은 기본값을 적용할 수 있었음 | ID, 프로젝트, 정상적인 숫자 점수가 없으면 주입하지 않음 |
| 긴 원문 조회 | 앞부분 최대 8,000자를 읽고 끝 | 시작 위치와 길이를 지정해 이어 읽기. 다음 위치와 남은 내용 여부 표시 |
| 대화 맥락 확인 | 검색 결과와 단일 기억을 별도로 확인 | 같은 대화의 앞뒤 수집 기록을 각각 최대 5개까지 함께 조회 |
| 출처 정보 | 조회 응답에 선택된 출처 필드가 없었음 | 세션, 수집 출처, 역할 등의 정보를 제공. 기록당 출처 문자열 2,048자와 source ID 16개로 제한하고 잘림 표시 |
| 설치 | Linux 서비스 설치 뒤 클라이언트 연결을 별도로 구성 | Linux/macOS 통합 setup, 지원 클라이언트 연결, 대화 수집, 설정 백업과 충돌 확인 후 복구 |

새 setup은 자동 회상 hook을 기본 등록하지 않습니다. Claude Code에서 자동 주입을 쓰려는 경우에만 `--autocontext`를 추가합니다. 이전에 등록한 hook은 사용자의 설정으로 보고 보존합니다.

## 그대로 유지하는 기능

- 기억 저장, 검색, 조회, 수정, 삭제의 기본 도구 5개.
- 대화 수집과 작업공간별 검색, 공유 `playbook`.
- `supersedes`로 이전 결정을 대체하고 검색에서 숨기는 정정 방식.
- 로컬 저장, 알려진 자격 증명 형태 가림, 별도 비밀 금고, 휴지통과 백업.
- 검색 결과별 최대 600자 발췌. 검색 전체에 새로운 글자 수 제한을 넣지 않았습니다.

자동 회상을 꺼도 에이전트가 필요에 따라 `memory_search`를 호출할 수 있고 `memnest watch`의 대화 저장도 계속됩니다. 기존 저장소를 삭제하거나 다시 수집할 필요는 없습니다.

## 업그레이드할 때 알아둘 점

1. **Pi의 자동 회상이 필요하면 직접 켜세요.** 시작 전에 `MEMNEST_AUTOCONTEXT_MODE=balanced`를 설정합니다. 기존 `aggressive`도 같은 검색 기준으로 동작합니다. 미설정, `off`, `none`, 잘못 입력한 값은 꺼짐으로 처리합니다. `MEMNEST_AUTOCONTEXT_DISABLE=1`이 항상 우선합니다. `/memnest`로 pi의 현재 설정을 확인할 수 있습니다.
2. **이미 설치된 Claude Code hook은 자동 삭제하지 않습니다.** 더 이상 원치 않으면 클라이언트 설정의 `UserPromptSubmit`에서 Memnest 명령만 제거하세요. Pi 설정과는 별개입니다.
3. **서버 쪽 페이지 조회와 주변 기록에는 새 코어와 확장이 모두 필요합니다.** 오래된 코어 응답은 pi가 로컬에서 글자 수를 제한하고 `paging: "client"`로 표시합니다. 다만 오래된 코어에서 `before`나 `after`를 요청하면 업그레이드 안내를 반환합니다. ID만 지정하는 기존 호출은 유지합니다.
4. **`memory_get` 표시 형식이 JSON 텍스트로 바뀝니다.** MCP나 pi 응답의 옛 표시 문자열을 직접 파싱하던 프로그램은 수정해야 합니다. 다음 위치와 출처 정보를 보존하기 위한 변경입니다.
5. **글자 수 제한은 토큰 제한이 아닙니다.** `max_chars`는 본문에 적용되고, 출처 정보에는 별도 상한이 있습니다. ID, 프로젝트명, 고정 필드와 JSON 표현 비용까지 합친 응답 전체를 제한하지는 않습니다.

## 정확도가 자동으로 좋아졌다는 뜻은 아닙니다

검색 모델과 순위 알고리즘은 바꾸지 않았습니다. 자동 회상을 켜면 점수가 높은 엉뚱한 기억이 여전히 포함될 수 있고, 생성 시각이 최신이라고 내용이 검증된 것도 아닙니다. 바뀐 사실은 정정해서 저장하고, 사용하기 전에 원문과 현재 상태를 확인해야 합니다.

앞뒤 기록은 Memnest가 **수집한 순서**입니다. 실제 대화의 전체 시간순이나 최종 결정을 보장하지 않으며, DB에 저장된 기록만 읽습니다.

MemoryBench 어댑터와 작은 한국어 검색 fixture, 독립 클라이언트 재현 데모도 추가했습니다. 이것은 비교 실험을 위한 기반입니다. 다른 제품보다 검색이나 답변이 더 정확하다고 입증한 결과는 아닙니다.

## 검증 범위

- Rust 테스트 113개, pi 자동 회상 회귀 검사 61개, 기본 도구 및 연결 검사, 설치 설정 검사 5개가 통과했습니다.
- Rust 전체 포맷 검사, 타입 검사, Linux 출시용 빌드가 통과했습니다.
- 임시 저장소에서 HTTP와 MCP의 페이지 조회, 출처 제한, 정정, 작업공간 분리를 확인했습니다. stdio MCP 검사와 기존 어댑터 검사도 통과했습니다.
- 코어 압축 파일과 npm 패키지를 실제로 풀었습니다. 테스트 드라이버가 배포용 pi 번들의 도구를 임시 서버에 연결해 저장, 검색, 이어 읽기, 수정, 삭제와 자동 회상 ID를 확인했습니다. 포장된 설치 스크립트의 명령행 실행과 설정 복구도 확인했습니다.
- 문서와 실제 엔드포인트를 대조하는 검사가 실패 없이 통과했습니다. 변경 경로의 언어 서버 검사도 통과했습니다. pi-lens 캐시에는 문서 링크 경고 4건이 남았지만, 해당 파일과 상대 경로가 존재함을 직접 대조했고 별도 언어 서버 재검사에서는 경고가 나오지 않았습니다.
- macOS는 설치와 패키징 코드를 제공하지만 이 Linux 환경에서 실제 launchd 설치, 로그인 후 자동 시작, 제거를 실행한 것은 아닙니다.
- 대규모 저장소 성능, 답변 정확도, 제품 간 비교 성능은 새로 측정하지 않았습니다.
