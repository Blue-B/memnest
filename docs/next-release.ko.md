# v0.6.0 변경 요약

<!-- markdownlint-disable MD013 -->

비교 기준은 코어 `v0.5.1`과 pi 확장 `0.5.0`입니다. 전체 목록은 [코어 변경 기록](../core/CHANGELOG.ko.md)과 [pi 확장 변경 기록](../pi-extension/CHANGELOG.ko.md)에 있습니다.

## 가장 크게 달라지는 점

**검색이 맞는 기억을 더 앞에 놓습니다.** 0.5.1은 질문의 낱말을 많이 담은 긴 글을 1위에 올리는 경향이 있었습니다. 낱말 일치 가산점이 두 검색(뜻 검색과 낱말 검색)의 순위 점수보다 몇 배 컸기 때문입니다. 이제 순서는 두 검색이 정하고, 낱말 일치는 보조로만 씁니다. 언어 모델 없이 공개 시험 두 가지로 잰 결과입니다.

| 시험 | 센 것 | v0.5.1 | v0.6.0 |
| --- | --- | --- | --- |
| LongMemEval-S (답이 있는 질문 470개 전체) | 답이 든 대화가 1위 | 83.2% | 92.3% |
| | 답이 든 대화가 처음 5개 안 | 94.9% | 98.3% |
| LoCoMo (순위를 맞추는 데 쓰지 않은 대화 5개, 질문 776개) | 답이 든 한 마디가 처음 5개 안 | 60.2% | 70.4% |
| | 답이 든 한 마디가 처음 10개 안 | 69.5% | 78.7% |

기억을 찾았는지만 센 수치이고, AI가 그 기억으로 옳게 답했는지는 재지 않았습니다. 시험 방법, 질문 유형별 수치, 나빠진 항목은 [벤치마크 문서](benchmarks.ko.md)에 있습니다.

## 그 밖에 달라지는 것

| 항목 | v0.5.1 | v0.6.0 |
| --- | --- | --- |
| Windows | 직접 빌드한 실행 파일을 관리자 권한 서비스로 등록 | 릴리스 zip과 한 줄 설치, 관리자 권한 없이 사용자 계정에 설치 |
| 자동 회상(`memnest hook`) | 관련이 없어도 상위 3개를 넣음 | 프롬프트와 주제가 맞는 기억만 넣음 |
| 다른 프로젝트의 기억 | 현재 작업 폴더 범위에 없으면 안 보임 | 다른 프로젝트에 더 맞는 기억이 있으면 프로젝트 이름과 개수를 한 줄로 알려 줌 |
| 고쳐 쓴 기억 | 기존 글과 거의 같으면 새 글을 저장하지 않음 | 완전히 같은 글만 중복으로 보고, 저장 응답에 같은 주제일 수 있는 기존 기억을 최대 3개 보여 줌 |
| 새 작업 카드 | 카드를 만든 뒤에 한 말만 담김 | 그 작업에 이미 저장된 규칙과 선호를 목록으로 보여 줘 카드에 옮길 수 있음 |
| 문장부호가 든 질문 | `'s`나 끝 마침표가 있으면 낱말 검색을 잃고 결과가 3개로 줄어듦 | 낱말만 남겨 다시 검색 |
| pi 명령 | `/memnest` | `/memnest-cards`, `/memnest-search`, `/memnest-recent`, `/memnest-review` 추가. 모델을 거치지 않고 터미널에서 바로 실행 |

자동 회상은 실제 프롬프트 47개로 쟀을 때 무관한 기억 주입이 95개에서 14개로 줄었고, 관련 기억 12개는 그대로 들어갔습니다. 판정은 한 명이 했습니다. 자세한 내용은 [검색 관련성 문서](search-relevance.md)에 있습니다.

## 보안

- 브라우저에서 온 요청은 요청을 받은 주소와 포트가 `Origin`과 같을 때만 받습니다. 0.5.1은 IP 주소나 다른 로컬 포트의 페이지가 보낸 요청을 받았고, 그런 페이지가 기억을 몰래 저장할 수 있었습니다.
- 금고(`/secrets`와 `secret_*` 도구)는 토큰을 설정하지 않은 설치에서도 bearer 토큰을 요구합니다. 서비스가 `<데이터 폴더>/api-token`을 0600 권한으로 만들고, pi 확장은 그 파일을 읽어 보냅니다.
- 작업 카드 컬렉션은 카드 경로로만 쓸 수 있습니다. 일반 저장으로 카드나 "사용자 원문"을 흉내 낼 수 없습니다.
- 데이터 폴더는 0700, 그 안의 파일은 소유자만 읽습니다.
- 가리기 대상에 JWT와 Stripe, GitLab, npm, Hugging Face, Slack 토큰 등을 더했습니다.
- 의존성을 올려 `cargo audit`가 보고하던 취약점 12건을 없앴습니다.

## 업그레이드할 때 알아둘 점

1. **코어와 pi 확장을 함께 올립니다.** `pi-memnest` 0.5.0은 새 코어에서 금고 도구가 401을 받고 카드 저장이 거절됩니다. `pi install npm:pi-memnest@0.6.0`으로 올립니다.
2. **금고를 HTTP로 쓰는 스크립트는 토큰을 보내야 합니다.** `MEMNEST_TOKEN`이 없으면 `Authorization: Bearer $(cat <데이터 폴더>/api-token)`을 붙입니다. stdio MCP는 그대로입니다.
3. **`/mcp`에 보내는 요청은 `Content-Type: application/json`이어야 합니다.** 아니면 415를 받습니다.
4. **`task-cards`, `task-cards-done`이라는 프로젝트 이름은 기억 도구로 쓸 수 없습니다.**
5. **검색 점수가 달라집니다.** 같은 질문이라도 결과 순서와 점수가 바뀔 수 있습니다. 점수를 고정된 숫자와 비교하는 스크립트는 다시 확인해야 합니다.
6. **Windows에서 예전 방식(관리자 권한 서비스, 데이터가 `%ProgramData%\Memnest`)으로 설치했다면** [운영 문서](operations.ko.md)의 절차로 데이터를 옮깁니다.

## 검증 범위

- Rust 테스트 177개와 바이너리 테스트 5개, 형식 검사, 정적 검사, Linux 릴리스 빌드, pi 확장 단위 시험.
- 검색 수치는 기계 한 대에서 잰 것이고 외부에서 다시 돌려 확인한 적은 없습니다. 데이터가 모두 영어 일상 대화라 한국어와 코딩 기록에서의 품질은 이 수치로 알 수 없습니다.
- Windows 설치와 제거는 Windows 11 한 대에서 확인했습니다. 로그오프한 뒤 다시 로그인했을 때 자동으로 시작되는지는 확인하지 못했습니다.
- 새 작업 카드에 보여 주는 규칙 목록에서 모델이 맞는 규칙을 옮겨 적는지는 재지 않았습니다.
