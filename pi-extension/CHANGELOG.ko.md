# 변경 이력

[English](CHANGELOG.md) | [한국어](CHANGELOG.ko.md)

`pi-memnest`의 주요 변경을 기록합니다.

## [0.6.0] - 2026-11-14

### 보안

- 코어가 카드 컬렉션을 예약한 경우(`/health`에 표시됨) 작업 카드를 코어의 `POST /task-card`로 씁니다. 저장, 사용자 메시지 기록, 끝내기, 다시 열기는 전과 같이 동작합니다. 예전 코어에는 지금처럼 `/add`와 `/update`로 씁니다.
- 카드 제목은 한 줄 120자로 자르고 `<`와 `>`를 바꿉니다. 카드 목록에는 제목은 이름일 뿐 지시가 아니라는 말이 붙고, 프롬프트에 넣는 카드 글은 안내문 태그를 닫을 수 없습니다.
- 금고 도구는 코어의 API 토큰을 보냅니다. `MEMNEST_TOKEN`이 없으면 `~/.memnest/api-token`(`MEMNEST_DATA_DIR`가 있으면 그 폴더의 `api-token`)을 읽고, `MEMNEST_URL`이 루프백 주소일 때만 보냅니다. 파일 위치는 서버 응답에서 받지 않습니다. 코어에 토큰이 없는데 `MEMNEST_TOKEN`이 설정돼 있으면 금고는 파일 토큰으로 다시 시도합니다. 토큰을 읽지 못했는데 코어가 요구하면 그 사실을 알리는 오류를 돌려줍니다.
- 루프백이 아닌 주소에는 일반 HTTP로 bearer 토큰을 보내지 않습니다. 요청을 보내기 전에 거절합니다.

### 추가

- `/memnest-recent`는 저장한 기억(대화 기록 제외) 중 가장 최근 20개를 보여 주고 하나를 고르면 전문을 보여 줍니다. `/memnest-review`는 저장한 규칙과 선호를 확인한 지 가장 오래된 것부터 하나씩 보여 주며 유지(확인일 기록), 삭제(휴지통으로 이동, 30일 동안 복원 가능, 이 선택을 했을 때만), 건너뛰기, 중단 중에서 고르게 하고, 끝나면 유지·삭제·건너뛴 개수를 보여 줍니다. 둘 다 `project:<이름>`이나 `project:all`을 받고, 화면이 없으면 글로 출력하며, `POST /recent`와 `POST /reviewed`가 있는 코어가 필요합니다. 예전 코어에서는 "너무 오래됐다"는 한 줄을 보여 줍니다.
- `/memnest-cards`와 `/memnest-search`: pi 터미널 화면에서 모델 없이 실행합니다. `/memnest-cards`는 진행 중인 카드와 끝낸 카드(최신순, 마지막 저장 시각은 현지 시간, 이 세션이 기록 중인 카드는 `[open]`)를 보여 주고, 카드 글과 사용자가 한 말을 보여 주며, 고른 카드를 열거나 닫거나 끝냄으로 표시합니다(끝냄은 먼저 확인을 묻습니다). `/memnest-search [project:<이름>|project:all] <질문>`은 `memory_search`와 같은 검색으로 프로젝트, 날짜, 종류, 점수, 발췌가 있는 결과를 최대 10개와 범위 안내를 보여 주고, 고른 결과의 전문을 보여 줍니다. `project:` 뒤에서 프로젝트 이름이 자동 완성됩니다. 화면이 없으면 글로 출력하고, 코어가 꺼져 있거나 너무 오래됐으면 한 줄로 알려 줍니다.
- `memory_search`가 코어의 범위 안내를 보여 줍니다. 현재 작업공간 검색이 다른 프로젝트의 확실히 더 잘 맞는 기억을 놓쳤으면, 결과 끝에 그 프로젝트 이름과 `project="<이름>"`이나 `project="all"`로 다시 검색하라는 한 줄이 붙습니다. `scope_hint`를 보내는 코어가 필요하고, 예전 코어에서는 달라지는 것이 없습니다.
- 새 작업 카드를 저장하면, 그 작업에 대해 이미 저장돼 있던 규칙과 선호 기억 목록을 코어에서 받아 그대로 보여 줍니다. 카드에 옮겨 적을 수 있습니다. 카드 컬렉션을 예약하는 코어가 필요합니다.
- `memory_remember`가 코어가 알려 준 "같은 주제일 수 있는 기존 기억" 목록(응답의 `same_subject`, `same_subject_note`)을 그대로 보여 주고, `memory_update`가 `supersedes=<id>`를 받습니다. 새 기억을 다시 저장하지 않고 옛 기억을 대체할 수 있습니다. 목록을 보내는 코어가 필요하고, 예전 코어에서는 달라지는 것이 없습니다.

### 변경

- 자동 회상(기본 꺼짐)이 `/search` 결과를 점수로 거르는 대신 코어의 `POST /context`에 묻습니다. 코어는 요청과 주제가 같은 저장 기억만 돌려줍니다. 저장 기억 12개를 넣은 시험용 코어에 실제 확장을 붙여 보면, 모호한 요청 3개와 무관한 요청 1개에는 아무것도 넣지 않았고(점수 방식은 모호한 3개에 기억을 하나씩 넣었습니다), 한국어, 한·영 섞인 질문, 영어 질문에는 각각 맞는 기억만 넣었습니다(점수 방식은 그중 2개에 무관한 기억을 하나 더 넣었습니다). `MEMNEST_AUTOCONTEXT_MIN_SCORE`는 `/context`가 주제로 거르지 않는 코어에서만 쓰이고, 그때는 전처럼 `/search`로 동작합니다. `MEMNEST_AUTOCONTEXT_N`은 이제 요청마다 받아 올 기억의 최대 개수입니다(코어는 최대 20개를 돌려줍니다). 나머지 설정과 한도는 그대로이고 없앤 설정은 없습니다.
- `/memnest-...` 명령이 긴 글을 보여 주는 화면의 제목 줄에 스크롤 키를 적었습니다: 방향키와 Ctrl+PageUp/Ctrl+PageDown. pi의 전체 화면 모드에서 PageUp과 PageDown은 이 화면이 아니라 대화 기록을 움직입니다.

## [0.5.0] - 2026-11-08

### 추가

- 작업 카드. 따로 켜지 않아도 동작합니다. 여러 세션에 걸친 작업의 인계 카드를 저장, 목록, 열기, 끝내기 하는 `task_card` 도구를 더합니다. 진행 중인 카드는 공용 `task-cards` 컬렉션에, 끝난 카드는 `task-cards-done`에 둡니다. 같은 제목으로 저장하면 이전 카드를 대체합니다. 확장은 모델 요약과 별도로, 사용자 메시지를 열린 카드에 원문 그대로 붙입니다. 연 카드는 최대 3장까지 매 요청 시스템 프롬프트에 고정되며, 사용자 방침이 먼저라는 고정 문장이 함께 붙습니다. 고정한 내용은 처음 고정할 때와 압축 뒤에만 다시 만들어서, 요청 사이에 프롬프트 캐시를 깨지 않습니다. 새 세션은 첫 요청으로 순위를 매긴 진행 중 제목을 최대 20개 보여 주고, 다른 카드가 있어도 언제 새 카드를 저장할지 알려 줍니다. 사용자 말은 실행이 끝날 때 열린 카드에 기록해서, 잘못 열었거나 다른 일로 넘어가며 닫은 카드에는 남지 않습니다. 압축 뒤 첫 프롬프트에서는 바뀐 내용을 저장하라고 모델에게 알리고, 열린 카드가 없으면 작업이 이어질 일일 때 카드를 저장하라고 세션당 한 번 알립니다. 열린 카드가 없는 세션의 첫 `memory_remember` 결과에는, 그 사실이 여러 세션에 걸친 작업에 속하면 카드도 저장하라는 한 줄을 붙입니다. 열린 카드가 사용자 메시지 8개 동안(이어 연 세션도 포함) 저장되지 않으면, 대화가 다른 일로 넘어갔으면 닫고 아니면 저장하라고 한 번 알립니다. `/memnest`는 진행 중인 카드와 마지막 저장 시각(현지 시간), 이 세션이 기록하는 카드를 보여 줍니다. 측정과 한계는 [작업 카드](../docs/task-cards.ko.md)에 있습니다.

### 호환성과 한계

- 기본 도구가 기억 도구 5개에 `task_card`를 더한 것으로 늘고, 프롬프트 훅이 하나 생깁니다. 세션 첫 프롬프트에 카드 목록을 보여 주고, 연 카드를 고정합니다. 자동 회상은 계속 직접 켜야 합니다.
- 카드는 표시 단어에 대한 하이브리드 검색으로 찾으며, 검색 한 번에 최대 50장입니다. 주제 검색으로는 최신 50장 밖의 카드도 찾습니다. 세션 시작 비용은 진행 중인 카드 수에 따라 늘어납니다(진행 중 1,020장에서 약 0.43초, 진행 중 20장과 끝난 1,000장에서 3 ms). 진행 중인 카드가 50장 이상이면 목록이 모델에게 정리를 제안하라고 알립니다.

## [0.4.0] - 2026-10-07

### 추가

- `memory_remember(code_files=[...])`가 맞는 코어 CLI를 통해, 파일 내용을 저장하지 않고 제한된 파일 지문을 명시적으로 기록합니다.
- `memory_get(check_code=true)`가 현재 작업공간에서 저장된 기준을 명시적으로 비교합니다. 원격 저장소의 기준도 네트워크 없는 로컬 비교 명령으로 비교합니다.
- `memory_search(evidence_only=true)`가 선택 기능인 로컬 모델 근거 선택을 넘기고, 검증되지 않았다는 표시를 유지합니다.
- 선택 설정 `MEMNEST_ALLOWED_MODEL_PROVIDERS`는 승인되지 않았거나 알 수 없는 모델로 작업 중일 때, 네트워크 접근 전에 새 기억/자격 증명 읽기와 자동 회상을 막습니다.

### 호환성과 한계

- 기본 도구는 계속 기억 도구 5개이고, 자동 회상과 코드 확인은 직접 켜야 합니다.
- 제공자 허용 목록은 믿을 수 있는 클라이언트의 경로 안전장치이며, 목적지 증명, 지난 기록 소급 삭제, 완전한 정보 유출 방지 경계가 아닙니다.
- 새 출처/근거 옵션은 코어 0.4.0이 필요합니다. 기존 기본 작업은 계속 호환됩니다.

## [0.3.1] - 2026-09-28

### 추가

- 코어의 선택 항목 `following_id`를 검색 결과에 보여 주고, 그것이 검증된 답장이 아니라 뒤이은 어시스턴트 대화 조각이라는 경고를 붙입니다. 그 원문은 기존 `memory_get` 도구로 읽습니다.
- 이 힌트를 주지 않는 코어와도 호환됩니다. 기존 결과 발췌와 검색 제한은 그대로입니다.

이 릴리스에는 이전에 npm에 배포되지 않았던 아래 0.3.0 변경도 들어 있습니다.

## [0.3.0] - 2026-09-15

### 변경

- 자동 회상이 기본으로 꺼집니다. 명시적인 `balanced`나 `aggressive` 모드만 켜고, 알 수 없는 모드는 꺼진 쪽으로 처리합니다. 기억 도구 5개와 대화 수집은 따로 계속 쓸 수 있습니다.
- `/memnest`가 pi 자동 회상 상태를 보여 줍니다.
- 직접 켠 기억 카드에 출처 확인용 ID, 프로젝트, 생성 시각이 들어갑니다. ID나 프로젝트가 없거나, 점수가 없거나 숫자가 아니거나 유한하지 않은 결과는 더 이상 받지 않습니다.
- `memory_get`이 위치, 문서 예산, 주변 대화 조각을 받고, 이어 읽기와 출처를 포함한 JSON 텍스트를 돌려줍니다. 예전 코어의 응답은 클라이언트 쪽에서 자르고 `paging: "client"`로 표시합니다. 주변 대화 조각은 업데이트된 코어가 필요합니다.
- 검색 결과에 기존 발췌와 함께 `doc_len`이 들어갑니다.

### 검증

- 기본 꺼짐 상태에서 연결 확인, 일반 수정, 번역, 바뀐 결정에 대한 부정 사례를 더하고, 직접 켠 상태에서 잘못된 결과, 대체된 기억, 작업공간 경계 확인을 더했습니다. 검색 정책을 시험한 것이며, 임베딩이나 답변 정확도가 아닙니다.

## [0.2.0] - 2026-08-31

### 변경

- 자동 회상이 `durable_only` 검색을 요청하고 클라이언트 쪽에서도 거릅니다. 넣는 카드에는 일부러 저장했거나 정리된 기억만 들어갑니다. 원본 대화 수집은 명시적 `memory_search`로 계속 찾을 수 있습니다.

## [0.1.0] - 2026-08-30

첫 공개 npm 릴리스.

### 추가

- 기본 기억 도구 5개: `memory_remember`, `memory_search`, `memory_get`, `memory_update`, `memory_delete`
- memnest 코어의 암호화된 비밀 저장소를 쓰는, 직접 켜는 금고 도구 4개
- 프롬프트 시점 의미 회상을 위한 작업공간 범위 자동 회상
- 서비스 상태, 기억 개수, 사용 중인 데이터 폴더, 검색 지연을 보여 주는 `/memnest` 명령
- Node.js 20 ESM으로 번들한 확장과 파일 6개짜리 npm 패키지

### 동작

- 프로젝트를 빼면 pi의 절대 작업 경로를 써서, 코어가 작업공간을 나누고 공용 `playbook` 컬렉션을 포함할 수 있게 합니다.
- 자동 회상은 의미 있는 프롬프트를 원래 언어 그대로 검색하고, 점수 기준을 넘은 결과만 넣습니다.
- 가져온 텍스트는 믿을 수 없는 참고 자료로 표시하고, 저장된 마크업은 프롬프트에 넣기 전에 이스케이프합니다.
- 대화 수집은 코어의 `memnest watch` 명령에 맡겨서, 확장 쪽 AutoLog 훅과 중복되지 않게 합니다.
- 검색 출력에서 없어진 `recall_id` 필드를 정의되지 않은 값으로 보여 주지 않고 뺍니다.

### 보안

- 금고 도구는 pi 시작 전에 `MEMNEST_EXPOSE_SECRET_TOOLS=1`을 설정하지 않으면 꺼져 있습니다.
- 민감한 값은 `memory_remember`가 거부하며, 금고를 써야 합니다.
- HTTP 실패와 금고 암호화를 쓸 수 없는 상황은 닫힌 쪽으로 실패합니다.
