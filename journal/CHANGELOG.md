# Changelog

All notable changes to `memnest-journal`.

## [0.1.0] — 2026-05-17

Initial public release.

### Added
- `pjournal init <dir>` — create a new journal repo with `.gitignore`.
- `pjournal export` — render memnest sqlite (`chunks`, `facts`, `notes`,
  `secrets`, `session_summaries`) into a markdown tree.
- `pjournal sync [--push] [--message]` — `export` + `git add` + `git commit`
  (and optional `git push`) in one shot.
- `pjournal import` — apply user edits in `*.md` back to memnest via
  `POST /add` with provenance markers
  (`<!-- memnest-journal: edited-from=<id> at=<iso> -->`).
- `pjournal log [-n N]` — show commit history of the journal repo.
- `pjournal status` — show pending markdown changes.
- `--include-sensitive` flag to opt-in to exporting `sensitive=true` chunks.
- `--project a,b,c` filter.
- `--since <iso>` filter.
- `--prune` to delete repo files for chunks that have disappeared from the DB.
- AES-GCM secrets are exported as ciphertext only; `master.key` is
  `.gitignore`-d by default.
- Smoke test (`test/smoke.mjs`) — 10 end-to-end assertions.

### Compatibility
- Node 20+ (uses `node:sqlite` when available).
- Bun 1.3+ (uses `bun:sqlite`).
- Fallback to `better-sqlite3` if neither built-in driver is present
  (optional install).

### Known limitations
- Memnest 0.1.x has no `PUT /chunks/:id` or `DELETE /chunks/:id`. An
  `import` therefore appends a new chunk with the same body plus a
  provenance comment; the original chunk is left intact and remains
  searchable for audit purposes. Use the `:format=html` dashboard or a
  future `pjournal forget <id>` once the API gains a delete endpoint.
- Vector embeddings are not regenerated by `import` — memnest's
  background indexer handles that on its own batching cadence (usually
  under 10s).
